# Актуализация волатильности по выгрузке из торгового терминала

**Дата:** 2026-08-10
**Тип:** feature (`/develop`)
**Статус:** реализовано, проверено тестами, ожидает проверки на реальном файле пользователем

---

## Зачем

Fact P&L и Fact IV вносились в сохранённые сделки вручную, по одной ноге. По регламенту это делается раз в неделю; при полусотне активных сделок — часы работы и риск опечаток. Терминал выгружает те же данные файлом.

## Что сделано

В Настройках появился подраздел «Актуализация Волатильности». Пользователь прикладывает CSV-выгрузку позиций, нажимает «Актуализировать» — система находит соответствующие ноги в активных сделках, записывает `P/L Open` → Fact P&L и `Impl Vol` → Fact IV, показывает отчёт.

## Формат файла

Заголовок таблицы — на 4-й строке, выше служебные строки.

```
Symbol,P/L Open,Pos Qty,Bid,Ask,Avg Price,Impl Vol
.AA261016C65,($232.65),+4,.83,1.10,$1.54,53.93%
.ADSK260918C240,"$1,767.34",+1,21.50,25.90,$6.02,57.44%
```

- `.CCI261016P67.5` → тикер CCI, экспирация 2026-10-16, PUT, страйк 67.5
- убыток записан скобками: `($232.65)` = −232.65
- суммы больше тысячи закавычены и содержат запятую разрядов

## Принятые решения (согласованы с заказчиком)

| Вопрос | Решение |
|---|---|
| Количество в файле — суммарное по счёту | Нога обновляется **только при совпадении** количества. Расхождения — в отчёт |
| Цена базового актива для якоря | Не считаем и не запрашиваем — кладём значение P/L как есть |
| Предпросмотр | Не нужен, применяем сразу |
| Уже заполненные значения | Всегда перезаписываем |
| Охват | Только активные сделки (`status = standard`) |
| Дата факта | Из имени файла, иначе сегодняшняя торговая дата ET (с пометкой в отчёте) |
| Ноги, которых нет в файле | Не трогаем, перечисляем в отчёте |
| Странные значения IV | Пишем без проверок |

## Известное ограничение

Цены базового актива в файле нет, поэтому `actualPLPrice` при импорте обнуляется — расчёт подставит текущую цену акции. Если файл загружается в день выгрузки, цифры сходятся; для старого файла якорь будет слегка смещён. Оставлять прежнюю цену рядом со свежим фактом нельзя — расчёт соединил бы факт этой недели с ценой месячной давности.

Снятие ограничения (запрос цен по тикерам при импорте) вынесено в предложения на будущее.

## Подводный камень: локальные правки браузера

Калькулятор хранит ручные правки ног в localStorage и накладывает их **поверх** данных из базы при открытии сделки. Без очистки свежеимпортированные значения были бы перекрыты старыми локальными — внешне это выглядело бы как «импорт не работает», хотя база уже обновлена.

Поэтому после успешного импорта фронтенд снимает локальные значения `actualPL*` и `manualIvOverride*` по обновлённым ногам (ключи приходят в отчёте). Прочие правки — количество, премия, дата входа — не трогаются.

## Безопасность (VERIFY)

- Размер файла ограничен 5 МБ, чтение идёт кусками с потолком — неограниченного чтения в память нет.
- Расширение файла проверяется, содержимое разбирается штатным CSV-парсером, никакого выполнения кода.
- Запросы к базе — только через ORM, конкатенации SQL нет.
- Секретов и ключей в коде нет.
- Аутентификация в проекте отключена глобально — эндпоинт наследует общее поведение остальных роутеров.
