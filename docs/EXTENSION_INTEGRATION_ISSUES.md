# Проблемы интеграции расширения с калькулятором

**Дата:** 29 марта 2026  
**Статус:** Требуется доработка расширения

## Проблема 1: Неправильная дата входа для новых опционов

### Описание проблемы
При добавлении нового опциона в уже открытую сохраненную позицию, дата входа (`entryDate`) устанавливается на дату создания конфигурации, а не на текущую дату.

### Ожидаемое поведение
- **Новый опцион в пустом калькуляторе**: `entryDate` = сегодняшняя дата ✅ (работает)
- **Новый опцион в открытой сохраненной позиции**: `entryDate` = сегодняшняя дата ❌ (не работает)

### Фактическое поведение
При добавлении нового опциона в открытую позицию (например, созданную 10 марта), новый опцион получает `entryDate = '2026-03-10'` вместо `entryDate = '2026-03-29'`.

### Причина
Расширение добавляет опцион **без поля `entryDate`** в объект опциона. Калькулятор пытается восстановить дату из конфигурации и использует `fallbackEntryDate` (дату создания конфигурации).

### Решение со стороны расширения

**Рекомендация:** При добавлении нового опциона в конфигурацию, расширение должно **явно устанавливать `entryDate`** на текущую дату.

```javascript
// ❌ НЕПРАВИЛЬНО (текущая реализация)
const newOption = {
  id: Date.now().toString(),
  action: "Buy",
  type: "CALL",
  strike: 205,
  date: "2026-04-24",
  quantity: 1,
  premium: 5.50,
  // entryDate отсутствует!
};

// ✅ ПРАВИЛЬНО (требуемая реализация)
const newOption = {
  id: Date.now().toString(),
  action: "Buy",
  type: "CALL",
  strike: 205,
  date: "2026-04-24",
  quantity: 1,
  premium: 5.50,
  entryDate: new Date().toISOString().split('T')[0], // Добавить это поле!
};
```

### Временное решение со стороны калькулятора
Калькулятор исключает `entryDate` из `savedOverrides` и устанавливает сегодняшнюю дату для опционов без `entryDate`. Однако это не идеальное решение, так как не различает "новый опцион" от "старого опциона без даты".

## Проблема 2: Автосохранение изменяет зафиксированные позиции

### Описание проблемы
При открытии сохраненной позиции и добавлении нового опциона **без явного сохранения**, конфигурация автоматически пересохраняется с новым опционом.

### Ожидаемое поведение
- Пользователь открывает сохраненную позицию
- Добавляет новый опцион для тестирования
- **НЕ** нажимает кнопку "Сохранить"
- Конфигурация **НЕ** должна измениться в localStorage

### Фактическое поведение
Конфигурация автоматически пересохраняется с новым опционом, даже если пользователь не нажал "Сохранить".

### Причина
Калькулятор имеет механизм автосохранения (строки 2688-2733 в `UniversalOptionsCalculator.jsx`), который срабатывает при изменении `options`. Этот механизм отключен для **зафиксированных позиций** (`isLocked = true`), но работает для обычных сохраненных конфигураций.

### Возможные решения

#### Вариант 1: Расширение не должно триггерить автосохранение
Расширение должно добавлять опционы **временно** (только в state), не обновляя localStorage конфигурации, пока пользователь явно не нажмет "Сохранить".

#### Вариант 2: Флаг "режим просмотра"
Расширение может устанавливать флаг `viewMode: true` при открытии сохраненной конфигурации, чтобы калькулятор не автосохранял изменения.

```javascript
// При открытии сохраненной конфигурации
const config = {
  ...savedConfig,
  viewMode: true, // Отключить автосохранение
};
```

#### Вариант 3: Отключить автосохранение в калькуляторе
Полностью отключить автосохранение и требовать явного нажатия кнопки "Сохранить". Это более безопасный подход, но менее удобный для пользователей.

### Рекомендация
**Вариант 1** — расширение не должно изменять localStorage при добавлении опционов в открытую конфигурацию. Только явное действие пользователя (кнопка "Сохранить") должно обновлять конфигурацию.

## Контракт взаимодействия расширения и калькулятора

### Структура опциона (обязательные поля)

```typescript
interface Option {
  id: string;                    // Уникальный ID (timestamp)
  action: "Buy" | "Sell";        // Действие
  type: "CALL" | "PUT";          // Тип опциона
  strike: number;                // Страйк
  date: string;                  // Дата экспирации (YYYY-MM-DD)
  quantity: number;              // Количество контрактов
  premium: number | null;        // Премия
  entryDate: string;             // ⚠️ ОБЯЗАТЕЛЬНО! Дата входа (YYYY-MM-DD)
  
  // Опциональные поля
  bid?: number | null;
  ask?: number | null;
  volume?: number | null;
  oi?: number | null;
  visible?: boolean;
}
```

### Правила добавления опционов

1. **Всегда устанавливать `entryDate`** при создании нового опциона
2. **Не изменять localStorage** при добавлении опционов в открытую конфигурацию
3. **Использовать ISO формат дат** (YYYY-MM-DD)
4. **Генерировать уникальный `id`** для каждого опциона

## Тестовые сценарии

### Сценарий 1: Добавление опциона в пустой калькулятор
1. Открыть пустой калькулятор
2. Добавить опцион через расширение
3. **Проверить:** `entryDate` = сегодняшняя дата

### Сценарий 2: Добавление опциона в сохраненную позицию
1. Открыть сохраненную позицию (создана 10 марта)
2. Добавить новый опцион через расширение (сегодня 29 марта)
3. **Проверить:** новый опцион имеет `entryDate = '2026-03-29'`
4. **Проверить:** старые опционы сохранили `entryDate = '2026-03-10'`

### Сценарий 3: Добавление опциона без сохранения
1. Открыть сохраненную позицию
2. Добавить новый опцион через расширение
3. **НЕ** нажимать кнопку "Сохранить"
4. Закрыть и снова открыть ту же позицию
5. **Проверить:** новый опцион **не должен** быть в конфигурации
