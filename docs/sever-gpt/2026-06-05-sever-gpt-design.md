# Спецификация: стратегия «Север GPT»

- **Дата:** 2026-06-05
- **Статус:** черновик на согласовании (перед реализацией)
- **Автор:** SDD / brainstorming

---

## 1. Контекст и цель

У платформы уже есть стратегия **«Север»** — она математически перебирает комбинации Buy Call + Buy Put к лонг-позиции по активу и подбирает наилучшие. «Север» остаётся **полностью без изменений**.

«Север GPT» — параллельная стратегия с тем же каркасом (кнопка → окно настроек → соединение с TradingView → сбор цепочки опционов → экран результата → перенос в калькулятор), но **математический подбор заменён на подбор через ChatGPT (OpenAI API)**. Собранная цепочка опционов и пользовательский промпт уходят в ChatGPT; он возвращает готовые комбинации, которые мы проверяем по реальным данным и показываем пользователю.

Цель: дать пользователю гибкий ИИ-подбор, управляемый текстовым промптом, при этом гарантируя, что в калькулятор попадают только реально существующие опционы с настоящими ценами.

---

## 2. Зафиксированные решения

| Тема | Решение |
|------|---------|
| Движок ИИ | **OpenAI ChatGPT** (отдельный ключ `OPENAI_API_KEY`, серверный вызов) |
| Результат | **Две комбинации за один запрос**: «Актив + опционы» и «Только опционы». По одной комбинации в каждом блоке |
| Ползунки/альтернативы | **Нет**. Никаких весов и списков альтернатив |
| Количество акций | В блоке «Актив + опционы» **ChatGPT сам решает** количество акций |
| Промпты | Библиотека на **сервере, общая** для всех пользователей |
| «Последний промпт» | **Единый для всех** (хранится на сервере), активен по умолчанию при открытии |
| Кнопки результата | На каждый блок — «Применить»; общие: «Подобрать заново», «Отклонить», «Вернуться к настройкам» |
| Кнопка запуска | **Сиреневая** «Север GPT» рядом с кнопкой «Север» |
| «Север» | **Не трогаем** ни одной строки |

---

## 3. Пользовательский поток

1. У пользователя есть лонг по активу и нет опционов → рядом появляются две кнопки: синяя «СЕВЕР» и сиреневая «СЕВЕР GPT».
2. Клик «СЕВЕР GPT» → открывается окно настроек; параллельно идёт **то же** соединение с TradingView (через расширение) и загрузка списка экспираций.
3. Пользователь заполняет те же поля, что и в «Севере», выбирает/редактирует **промпт**, жмёт «Подобрать через ChatGPT».
4. Расширение разворачивает цепочку выбранной экспирации → фронтенд получает полную цепочку.
5. Фронтенд отправляет на сервер: параметры + промпт + отфильтрованную цепочку. Сервер строит промпт, вызывает ChatGPT, получает **две** комбинации, проверяет их по реальной цепочке и возвращает готовые.
6. Экран результата: два блока («Актив + опционы», «Только опционы»), по одной комбинации в каждом + пояснение ChatGPT.
7. Пользователь: «Применить» (на нужном блоке) / «Подобрать заново» / «Отклонить» / «Вернуться к настройкам».
8. «Применить» переносит комбинацию в калькулятор; появляется сиреневый значок «Подбор СЕВЕР GPT» с кнопками «К результатам» и «Отменить».

## 4. Окно настроек

Точно такое же, как у «Севера» (цель по верху/низу, экспирация, дата расчёта, диапазоны Call/Put страйков, допуск P&L, маржин и допуск, мин. доля акции), **плюс блок промпта**.

### Механизм промптов

- **Библиотека** — список именованных промптов на сервере, общий для всех.
- **Выпадающий список** сохранённых промптов + **текстовое поле** с самим промптом.
- Выбор из списка → текст подставляется в поле. Поле можно отредактировать под текущую задачу.
- Кнопки: «**Сохранить как новый**» (с названием), «**Обновить выбранный**» (перезаписать текст), «**Переименовать**», «**Удалить**».
- Если текст в поле отличается от сохранённого промпта — пометка «**изменён**».
- **В подбор всегда уходит текст из поля** (с учётом несохранённых правок).

### Что активно по умолчанию при открытии

1. **Последний использованный** промпт (тот, с которым в прошлый раз запускали подбор) — определяется по серверной метке времени последнего использования;
2. если такого нет — **самый свежий** из библиотеки;
3. если библиотека пуста — **встроенный шаблонный** промпт (`DEFAULT_NORTH_GPT_PROMPT`).

«Последний использованный» обновляется на сервере в момент запуска подбора с выбранным сохранённым промптом. Если подбор запущен с несохранённым (ad-hoc) текстом — метка не двигается.

## 5. Экран результатов

Два блока рядом (на узком экране — друг под другом):

- **Левый — «Актив + опционы»**: одна комбинация (рекомендованное ChatGPT количество акций + опционы).
- **Правый — «Только опционы»**: одна комбинация (только опционы поверх текущей позиции).

В каждом блоке:
- Карточка комбинации (ноги Call/Put: количество, страйк, цена; для «актив+опционы» — количество акций; маржин/стоимость; ключевые P&L-метрики на цели по верху и закрытии по низу).
- Краткое **пояснение ChatGPT**, почему выбрана эта комбинация.
- Кнопка «**Применить**» (применяет именно этот блок).

Блоки — это **альтернативы**: пользователь применяет **один** из двух. После применения значок «Подбор СЕВЕР GPT» появляется, кнопка запуска прячется (как в «Севере»).

Общие кнопки снизу:
- «**Подобрать заново**» — повторный запрос к ChatGPT с теми же параметрами и промптом, **без** повторного сбора цепочки (используется уже собранная). Обновляет оба блока.
- «**Отклонить**» — закрыть/отбросить результат, ничего не применяя.
- «**Вернуться к настройкам**» — назад в форму параметров (собранная цепочка сохраняется).

Если ChatGPT не смог собрать валидную комбинацию для одного из блоков — в этом блоке показываем сообщение об ошибке, второй блок при этом остаётся рабочим.

---

## 6. Защита от ошибок ИИ (валидация)

ChatGPT отвечает в **строгом формате** (JSON-схема). Каждую полученную ногу сервер **сверяет с реальной цепочкой** из TradingView:
- страйк должен реально существовать для выбранной экспирации и типа (Call/Put); несуществующий/выдуманный страйк — отбрасывается (без подмены далёким);
- страйк должен попадать в заданные пользователем диапазоны;
- цены/греки/IV **берутся из реальной цепочки**, а не из ответа модели (модель их вообще не присылает);
- дубли ног (тот же тип+страйк) суммируются по количеству;
- если не осталось ни одной валидной ноги — блок помечается ошибкой.

Итог: в калькулятор **физически не может** попасть несуществующий опцион или выдуманная цена.

- Никаких изменений в файлах `frontend/src/components/CalculatorV2/NorthStrategy/*`, `frontend/src/utils/northStrategy/analyzer.js`, `scoring.js`.

- Единственный общий компонент, который переиспользуем для отображения, — `ResultCard.jsx` (без изменений; при желании отдельного сиреневого заголовка — только **добавить** ключ палитры, не меняя существующие).

## 8. Инструкция по настройке OpenAI / ChatGPT (для владельца)

Отдельный «бот» или «свой GPT» создавать **не нужно** — наш сервер сам обращается к ChatGPT через API. Нужен только ключ доступа:

1. Зайти на **platform.openai.com** (платформа для разработчиков, не обычный чат), войти/зарегистрироваться.
2. **Billing** → добавить карту и небольшой баланс ($5–10 хватит на двоих).
3. **Billing → Limits** → задать низкий месячный потолок (например $10), чтобы перерасход был невозможен.
4. **API keys** → «Create new secret key» → скопировать ключ (`sk-...`, показывается один раз).
5. **Передать ключ разработчику** для установки на сервер (`.env`, `OPENAI_API_KEY`). **Никуда больше не вставлять** — ни в браузер, ни во фронтенд, ни в чат, ни в git.
6. Модель по умолчанию — экономичная (`gpt-4o-mini`). При желании «поумнее» — переключить на `gpt-4o` одной настройкой, без переделки.

### 9.2 Бэкенд

- `backend/app/services/openai_client.py` — **новый** клиент по образцу `gemini_client.py`: читает `OPENAI_API_KEY`, `OPENAI_MODEL` (по умолчанию `gpt-4o-mini`), температуру/лимит токенов; метод `select_combinations(payload)` со **строгим structured output** (`response_format` JSON-schema, `strict: true`); шаблон системного промпта из `backend/app/prompts/north_gpt_prompt.md`; типизированная обработка ошибок (timeout/rate limit/auth).

- `backend/app/routers/north_gpt.py` — **новый** роутер, префикс `/api/north-gpt`, зарегистрировать в `backend/app/main.py`:
  - `POST /select` — приём `{ params, prompt, chain, context }`; предфильтр цепочки (экспирация + диапазоны страйков + `ask>0 & iv>0`); вызов ChatGPT; **валидация/восстановление** обеих комбинаций по цепочке; сборка полных снимков ног (Python-аналог `buildOptionPosition`: `action='Buy'`, `premium=ask`, греки/IV из цепочки, `assetPriceAtEntry` из контекста); расчёт `cost`; ответ `{ status, withAsset, optionsOnly }`. P&L-метрики (`criteria`/`meta`) досчитываются на фронте.
  - CRUD промптов под `/api/north-gpt/prompts` (см. §9.5).
- `backend/.env.example` — добавить блок OpenAI; `backend/requirements.txt` — добавить `openai>=1.40.0`.

### 9.3 Контракт структурированного ответа ChatGPT (строгий)

```jsonc
{
  "with_asset": {
    "legs": [ { "option_type": "CALL|PUT", "strike": number, "quantity": integer>=1, "side": "BUY" } ],
    "stock_quantity": integer >= 0,   // количество акций, выбранное ChatGPT
    "rationale": "краткое пояснение на русском"
  },
  "options_only": {
    "legs": [ { "option_type": "CALL|PUT", "strike": number, "quantity": integer>=1, "side": "BUY" } ],
    "rationale": "краткое пояснение на русском"
  }
}
```

Модель присылает **только** тип/страйк/количество/сторону + количество акций + пояснение. Всё остальное (цены, греки, стоимость, P&L) восстанавливается из реальной цепочки и никогда не берётся из ответа модели.

### 9.4 Алгоритм валидации/восстановления (на каждую из двух комбинаций)

1. Отфильтровать цепочку: нужная экспирация, `ask>0 & iv>0`, построить индекс `{(тип, страйк): строка}`.
2. Для каждой ноги: проверить тип/сторону; найти страйк в индексе (нет точного совпадения → отбросить, без подмены далёким); проверить попадание в диапазон; подставить реальные `bid/ask/iv/греки`, `premium=ask`; объединить дубли.
3. Если валидных ног не осталось → блок = ошибка с понятным сообщением.
4. `with_asset`: `stock_quantity>0` → режим «актив+опционы»; иначе трактуем как «только опционы». `options_only` всегда без акций.
5. Собрать `cost` (`optionsCost = Σ ask*100*qty`, `stockMargin`, `marginUsed`, доля акции).

### 9.5 Хранение промптов (модель + эндпоинты)

`backend/app/models/north_gpt_prompt.py` — **новая** модель по образцу `saved_configuration.py`, **без привязки к пользователю**:
- таблица `north_gpt_prompts`: `id` (UUID), `name`, `text`, `created_at`, `updated_at`, `last_used_at` (nullable).
- зарегистрировать импорт в `init_db()` (`backend/app/database.py`) — таблица создастся автоматически.

Эндпоинты (в том же роутере, префикс `/api/north-gpt/prompts`):
- `GET /` — список, сортировка по `last_used_at desc, updated_at desc` (первый = «последний использованный»).
- `POST /` `{name, text}` — создать.
- `PUT /{id}` `{name?, text?}` — обновить (перезапись текста / переименование).
- `DELETE /{id}` — удалить.
- Отметка «последний использованный» обновляется в `POST /select`, если передан id выбранного сохранённого промпта (бамп `last_used_at = now`).

## 10. Граничные случаи и риски

- **Галлюцинации страйков** — отбрасываются на валидации; подмены далёким нет.
- **Несовпадение цен** — невозможно: цены всегда из живой цепочки.
- **Контроль токенов/стоимости** — двойной предфильтр (фронт + бэк), компактный формат цепочки в промпте, дешёвая модель по умолчанию.
- **Задержка** — индикатор «ChatGPT подбирает…», кнопки заблокированы на время запроса; «Подобрать заново» использует уже собранную цепочку.
- **Ошибки OpenAI** (timeout/rate limit/нет ключа) — понятные русские сообщения, показываются в блоке результата с кнопкой «Подобрать заново».
- **Пустой/битый ответ** — строгий JSON-schema минимизирует; дополнительно guard на ноль валидных ног.
- **Передача ограничений модели** — числовые параметры (цели, маржин, допуски, диапазоны, мин. доля акции) кладём в промпт как жёсткие правила, но финальная безопасность — серверная валидация.
- **Изоляция стратегий** — «Север GPT» инжектит/отменяет только `fromNorthGptStrategy`, «Север» — только `fromNorthStrategy`.
- **Шаг страйков** — сопоставление по реальным страйкам цепочки (не предполагаем кратность 5).

## 11. План проверки (end-to-end)

1. Локально поднять бэкенд (с `OPENAI_API_KEY` в `.env`, `pip install`) и фронт; TradingView с расширением.
2. Позиция: лонг по активу, без опционов → видны обе кнопки, сиреневая — GPT.
3. Клик «СЕВЕР GPT» → экспирации грузятся **той же** командой расширения.
4. Заполнить параметры, выбрать/ввести промпт, запустить → расширение разворачивает цепочку → POST `/api/north-gpt/select`.
5. Экран результата: два блока с одной комбинацией каждый + пояснения; ползунков нет.
6. «Применить» на блоке → ноги попадают в калькулятор с `fromNorthGptStrategy`, появляется сиреневый значок; страйки/цены совпадают с реальной цепочкой.
7. «Подобрать заново» → повторный запрос без пересбора цепочки; «Отклонить» → отбрасывает; «Вернуться к настройкам» → назад в форму.
8. Промпты: создать/выбрать/обновить/переименовать/удалить; «последний использованный» активен по умолчанию при повторном открытии (в т.ч. в другом браузере — общий).
9. **Регресс «Севера»**: пройти старый сценарий — поведение не изменилось; применение «Севера» и «Север GPT» не удаляют ноги друг друга.
10. Тесты валидации (мок-ответ): несуществующий страйк, страйк вне диапазона, дубли, пустые ноги.
