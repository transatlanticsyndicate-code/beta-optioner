# Тип позиции в Крипто Менеджере — спецификация

Дата: 2026-09-21
Страница: `crypto.optioner.online/#crypto` (папка `crypto/`, Vite + TypeScript)

## Задача

У позиции сейчас есть единственный настраиваемый параметр — «Сценарий». Нужен второй параметр — «Тип позиции»
(монеты, акции, сырьё, индексы, облигации, ETF) с управляемым списком, колонкой в таблице, сортировкой и счётчиками.

## Решения, принятые с заказчиком

1. Существующие позиции остаются **без типа** (прочерк), тип проставляется вручную.
2. Счётчик позиций по типу показывается **только в форме добавления и в фильтре** («Монеты (12)»), не в строках таблицы.
3. Удаление типа, который используется позициями, **запрещено** (сообщение с числом позиций).
4. Строки таблицы получают **режим редактирования** (как в «Финансовом учёте»): карандаш → поля → галочка/крестик.
   Редактируются тикер, сценарий и тип. Вне режима редактирования все три поля — просто текст.

## Модель данных

- `Asset.typeId?: string` — ссылка на тип; отсутствует/пусто = «без типа».
- `State.positionTypes: PositionType[]`, где `PositionType = { id: string; name: string }`.
  Значение по умолчанию при первой загрузке: монеты, акции, сырьё, индексы, облигации, ETF.
- Миграция: при загрузке из localStorage и из облака отсутствующий `positionTypes` заполняется набором по умолчанию;
  `typeId` у существующих активов не проставляется. Валидация состояния не должна отвергать старые документы.

## Интерфейс

### Настройки (панель «шестерёнка» крипто-страницы)

Блок «Типы позиций» под настройкой сценариев: таблица с названием типа (редактируется на месте) и кнопкой удаления,
кнопка «+ Добавить тип».

Защита от дурака:
- пустое или состоящее из пробелов название не сохраняется (возврат к прежнему значению);
- дубликат названия (без учёта регистра и пробелов по краям) отклоняется сообщением;
- удаление типа, используемого хотя бы одной позицией, отклоняется: «Тип используется в N позициях…»;
- удаление неиспользуемого типа — через подтверждение.

### Таблица

- Новая колонка «Тип позиции» сразу после «Сценарий». Значение — текст, у позиций без типа — «—».
- Колонка «Сценарий» в обычном режиме тоже становится текстом (сейчас это замаскированный выпадающий список).
- В служебной колонке рядом с крестиком удаления появляется карандаш.
- Режим редактирования строки: тикер — поле ввода (только латиница и цифры, верхний регистр),
  сценарий — выпадающий список, тип — выпадающий список с пунктом «Без типа». Галочка сохраняет, крестик отменяет.
  Одновременно редактируется не более одной строки.
- Защита при сохранении: пустой тикер отклоняется; тикер, совпадающий с другой позицией, отклоняется сообщением.

### Форма добавления и фильтры

- В форме добавления — список «Тип позиции» рядом со «Сценарий», пункты вида «Монеты (12)», плюс пустой пункт.
  Тип необязателен: кнопка «+ Добавить» по-прежнему требует только тикер и сценарий.
- В блоке фильтров — список «По типу» рядом с «По сценарию», с теми же счётчиками и пунктом «Без типа».
- Кнопка сброса фильтров очищает и фильтр по типу.

### Сортировка

Клик по заголовку «Тип позиции» переключает: А→Я → Я→А → сброс (как «Актив» и «Ордера»).
Позиции без типа всегда в конце списка при обоих направлениях. Индикатор — стрелка в заголовке.

## Границы работы

Не входит: изменение расчётов, статистики, страниц «Финансовый учёт» и «Еженедельная статистика»,
экспорт/импорт меняется только в части нового поля (переносится «как есть» вместе с состоянием).

## Проверка

- Сборка `npm run build` в `crypto/` без ошибок TypeScript.
- Ручной сценарий: добавить тип, переименовать, попытаться удалить используемый (запрет), удалить неиспользуемый;
  завести позицию с типом и без; отредактировать строку; отсортировать по колонке; отфильтровать по типу;
  перезагрузить страницу и убедиться, что данные сохранились.
- Безопасность: названия типов и тикеры экранируются при выводе в HTML (защита от XSS), секретов в коде нет.
