## 1. BSM: формулы, дисконтирование, дивиденды (Мертон)

`frontend/src/utils/blackScholes.js:35-89`

```
d1 = (ln(S/K) + (r − q + σ²/2)·T) / (σ√T);  d2 = d1 − σ√T
CALL = S·e^(−qT)·N(d1) − K·e^(−rT)·N(d2)
PUT  = K·e^(−rT)·N(−d2) − S·e^(−qT)·N(−d1)
```

**Канон соблюдён полностью.** Знак и место `q` верны (в дрейфе `r − q`, множитель
`e^(−qT)` только при `S`), страйк дисконтируется по `r`, пут — по паритету.

Проверка пут-колл паритета на модели (S=230, K=240, T=60д, r=4.5%, q=0.5%):
невязка `C − P − (S·e^(−qT) − K·e^(−rT)) = 2.8e−14` — машинная точность. **OK.**

Греки (`blackScholes.js:104-163`) также каноничны с поправкой на дивиденды:
Δ_call = e^(−qT)N(d1), Δ_put = e^(−qT)(N(d1)−1), Γ и Vega с множителем e^(−qT),
Θ с членами `+qSe^(−qT)N(d1)` / `−qSe^(−qT)N(−d1)` — всё верно.

Black-76 (`black76.js:53-191`): `d1` корректно **без** `r`, цена = `e^(−rT)[F·N(d1) − K·N(d2)]`,
Θ = `r·C − e^(−rT)F·n(d1)σ/(2√T)`, ρ = `−T·C`. Все формулы совпадают с каноном. **OK.**

### 1.1 «Пол» по внутренней стоимости — фактически частичная американская поправка

`optionPricing.js:165-171` и `futuresPricing.js:160-162`:
```
timeValue = max(0, bsPrice − intrinsic);  return intrinsic + timeValue
```
Это `max(BS_европ, intrinsic)`. Направление верное (нижняя граница американского
опциона), побочных эффектов не даёт: для колла без дивидендов пол никогда не
срабатывает (BS ≥ S − K·e^(−rT) > S − K). Для глубоких путов срабатывает и
**полностью снимает** ошибку (см. §5).

## 2. Время: t = календарные дни / 365

Единая цепочка: `dateUtils.calculateDaysRemainingUTC` (`dateUtils.js:127-190`) →
`optionPricing.js:143` / `futuresPricing.js:140` → `T = max(0, days)/365`.

* Конвенция «календарные/365» — отраслевой стандарт и согласована с тем, как
  котируется IV. **Соответствует науке.**
* Все даты приводятся к `Date.UTC(y,m,d)` (полночь), разность всегда кратна
  86 400 000 мс → `Math.ceil` не даёт off-by-one, DST не влияет. **OK.**
* Отрицательное `t` невозможно: клампы `Math.max(0, …)` стоят и в `dateUtils.js:189`,
  и в `optionPricing.js:143`, и в `blackScholes.js:67`.
* `t → 0` и ровно на экспирации: `T ≤ 0` → чистая внутренняя стоимость
  (`blackScholes.js:66-71`, `optionPricing.js:146-148`). Разрыва/скачка нет,
  временная стоимость монотонно вырождается. **OK.**
* Единственное расхождение с реальностью: экспирация трактуется как полночь UTC,
  а не 16:00 ET. День до экспирации при этом «полный». Цена одного дня для
  ATM 90д ≈ **$7.8/контракт**, для OTM 60д ≈ **$5.9/контракт**; систематический
  сдвиг ≈ полдня ≈ **$3–4/контракт ≈ $15–20 на типовую сделку**.
  Это примерно и есть наблюдаемая медиана расхождения ~$20.

## 3. Единицы IV: проценты vs доли

Цепочка вызовов согласована:

| Точка | Формат | Файл:строка |
|---|---|---|
| Polygon / TV extension | доли | `polygon_client.py:354` |
| нормализация при импорте | доли (`n>1 ? n/100 : n`) | `hooks/useExtensionData.js:100`, `northStrategy/analyzer.js:77-81`, `northGptStrategy/enrich.js:222` |
| `getOptionVolatility` / `getProjectedIV` | **проценты** (25 = 25%) | `volatilitySurface.js:378-487`, `:180-226` |
| `overrideVolatility` в BSM | `>1 ? /100 : as-is` | `optionPricing.js:132-137`, `futuresPricing.js:130-134` |

Явных ошибок ×100/÷100 в живом пути нет. Но правило `>1 ? /100` **неоднозначно**
на двух краях:

* **IV в долях > 1 (т.е. > 100%)** превращается в 1/100 своего значения.
  Пример: биотех/мем-акция с IV = 120% (хранится как `1.2`) → модель считает 1.2%.
  Колл 60д OTM: вместо $5.18 модель даёт $0.000000 → **ошибка $518 на контракт**.
  В текущей базе (44 сделки, IV 20–60%) не проявляется, но это мина.
  Файл: `optionPricing.js:134`, `futuresPricing.js:131`, `volatilitySurface.js:184`.
* **IV в долях в диапазоне (0; 0.05)** отбрасывается фильтром
  `optionPricing.js:75` и подменяется `DEFAULT_VOLATILITY = 0.30`.
  При реальной IV = 4% модель даёт $2.72 вместо $0.00 → **$272 на контракт**.
  Практически недостижимо для акций, но фильтр «5%…500%» научно ничем не оправдан.
* `getImpliedVolatility` (`optionPricing.js:63-83`) содержит `console.log` на
  **каждом** вызове — при построении графика это тысячи логов на кадр. Не ошибка
  математики, но производительность.

## 4. Безрисковая ставка

* Источник: FRED серия **DGS3MO** (3-мес. T-Bill) — правильный тенор для опционов
  1–3 мес. `backend/app/services/treasury_rate_service.py:17`.
* Fallback 4.5% зашит в трёх местах: `treasury_rate_service.py:19`,
  `backend/app/main.py:190`, `frontend/src/hooks/useRiskFreeRate.js:14`. Согласованы.
* **Гонка на старте:** `getRiskFreeRateSync()` (`useRiskFreeRate.js:144-150`) читает
  только `localStorage`. При первом рендере до завершения `fetch` все расчёты идут
  на 4.5%. Разница между 4.5% и, скажем, 4.0% для ATM 90д ≈ $12/контракт
  (dC/dr ≈ K·T·N(d2)); ошибка держится доли секунды и исчезает при перерисовке. Мелочь.
* DGS3MO котируется как простая годовая ставка, в формулу подставляется как
  непрерывная. Разница ln(1+y) vs y при 4.5% ≈ 10 б.п. → **< $1/контракт**. Пренебрежимо.
* **Крипта r = 0** (`universalPricing.js:84,137`; `PLChart.jsx:105`;
  `OptionsTableV3.jsx:209`). Формально «нет безрисковой ставки» — неверная мотивировка.
  Правильная величина для крипто-опциона — **форвардный базис** (r − q ≈ базис
  фьючерса к споту), а не ноль. При типичном контанго BTC 6% годовых:

  | Позиция (BTC, спот 100k, IV 50%) | модель r=0 | рынок (базис 6%) | расхождение |
  |---|---|---|---|
  | CALL 110k, 30д | $2 275 | $2 403 | **−5.3%** |
  | CALL 120k, 60д | $2 226 | $2 420 | **−8.0%** |
  | CALL 130k, 90д | $2 104 | $2 342 | **−10.2%** |
  | PUT 80k, 60д | $1 238 | $1 118 | **+10.7%** |

  То есть в крипторежиме коллы систематически **недооценены на 5–10%**, путы
  переоценены на столько же. На премии $2 000 это **$100–240**. Это самая
  крупная модельная неточность из найденных. (Крипто-таб `BinanceDealTab.jsx:354`
  использует свой отдельный ввод ставки с дефолтом 3.7% — там проблемы нет,
  но это второй, несогласованный путь; см. §6.)

* **Backend** `stocks_pl_calculator.py:28` и `futures_pl_calculator.py:23` имеют
  дефолт **5%**, а `options_universal.py:56,69` — тоже 5%. Расходится с фронтом.
  Роутер `/api/universal/*` фронтом **не вызывается** (единственный вызов —
  `/api/universal/tradingview/status`, `UniversalOptionsCalculator.jsx:226`),
  т.е. это мёртвый код, но при оживлении даст расхождение.
* `utils/greeksCalculator.js:28` — жёстко `r = 0.05` и `sigma = pos.iv || 0.5`
  **без** нормализации процентов в доли (при iv=73 получится σ=7300%). Файл никем
  не импортируется — мёртвый код, но опасный.

## 5. Американский стиль исполнения — величина ошибки

Модель европейская (+ пол по intrinsic). Сравнение с CRR-деревом с ранним
исполнением, r=4.5%, $ на 1 контракт:

| Позиция | Европ. | Америк. | Модель (с полом) | Недооценка |
|---|---|---|---|---|
| OTM call 60д, q=0 | 2.238 | 2.237 | 2.238 | **$0.00** |
| OTM call 60д, q=2% | 2.113 | 2.113 | 2.113 | **$0.00** |
| OTM call 90д, q=4% (дивид. акция) | 0.875 | 0.875 | 0.875 | **$0.00** |
| OTM put 60д (S=230,K=200) | 1.427 | 1.438 | 1.427 | **$1.09** (0.8%) |
| OTM put 90д (S=500,K=420) | 4.336 | 4.377 | 4.336 | **$4.16** (1.0%) |
| ATM put 90д | 10.739 | 10.913 | 10.739 | **$17.5** (1.6%) |
| ITM put 90д (S=180,K=200) | 22.280 | 22.795 | 22.280 | **$51.6** (2.3%) |
| глубокий ITM put 90д (S=150,K=200) | 48.110 | 50.000 | **50.000** | **$0.00** ← пол сработал |
| ITM call 90д, q=3% | 20.615 | 20.615 | 20.615 | **$0.02** |

**Вывод по профилю базы (дальние OTM, 1–3 мес.):**

* **Коллы — ошибка тождественно ноль**, включая дивидендные. Ранняя эксплуатация
  американского колла оптимальна только непосредственно перед экс-дивидендом при
  глубоком ITM; для OTM-коллов 1–3 мес. премия раннего исполнения ≈ 0.
* **Путы — недооценка 0.8–1.0% премии** для OTM, т.е. **$1–4 на контракт**,
  **$5–20 на типовую сделку $2 000**. Растёт до 1.6% для ATM и 2.3% для умеренно ITM.
* Глубокие ITM-путы **защищены полом** по intrinsic — ошибка ровно 0.
  Хуже всего середина (ATM…ITM 10%), но она в базе почти не встречается.

**Итог: для рабочего профиля сделок американская поправка пренебрежима**
(порядок $5–20 на сделку, тот же масштаб, что наблюдаемая медиана $20).
Внедрять BAW/биномиальное дерево ради этого не требуется.

**Отдельно — дивиденды.** Здесь ошибка больше, чем от американости:
если `q` не подгрузился или тумблер «учитывать дивиденды» выключен
(`UniversalOptionsCalculator.jsx:384-388, 4340`), OTM-колл 60д переоценивается:
q=1% → **$6.3/контракт**, q=2% → **$12.5**, q=4% → **$24.4**.
На 5 контрактах это **$30–120** — крупнее американской поправки в 3–6 раз.
Дополнительно: `q` берётся как непрерывная доходность = сумма дивидендов за 12 мес.
/ цена (`polygon_client.py:670`). Для 1–3 мес. это корректно, **если** в окне
опциона нет экс-дивидендной даты; если есть — непрерывное приближение занижает
дисконт (порядок ±$3–8 на контракт для 2%-ного дивиденда).

**Замечание:** строка `UniversalOptionsCalculator.jsx:825` передаёт в снимок
калькулятора сырой `dividendYield`, **игнорируя** тумблер `useDividends`
(во всех остальных 6 местах — `useDividends ? dividendYield : 0`). Несогласованность.

## 6. P&L, множители, effective premium

Формула (`optionPricing.js:258-264`, `futuresPricing.js:203-209`):
```
Buy:  (theoretical − entry) × |quantity| × multiplier
Sell: (entry − theoretical) × |quantity| × multiplier
```
**Канонично.** `quantity` берётся по модулю (`getQuantity`), направление — только
через `action`, двойного учёта знака нет.

Множители:
* акции/ETF — 100 (`optionPricing.js:5`, `universalPricing.js:136,177`);
* крипта — 1 (`universalPricing.js:136`, `UniversalOptionsCalculator.jsx:211`);
* фьючерсы — `pointValue` (`futuresPricing.js:205`).
**Живой путь передаёт `contractMultiplier` явно во все вызовы** (`PLChart.jsx:97-120`,
`OptionsTableV3.jsx:213`), так что дефолт 100 внутри `getMultiplier` не срабатывает.

Найденные дыры по множителю (не в основном пути, но реальные):
* `UniversalOptionsCalculator.jsx:208-214` — в режиме FUTURES при `selectedFuture == null`
  множитель падает на **100**, а не на `pointValue`. Для ES (pointValue 50) это ошибка ×2.
* `metricsCalculator.js:412-414` (`calculateOptionPL`) вызывает P&L **без** множителя →
  всегда 100. Функция экспортируется, но снаружи не используется — мёртвая.
* `northStrategy/analyzer.js:136-142` не передаёт `pointValue` (дефолт 1); для акций
  безразлично, для фьючерсов дало бы множитель 1. `northGptStrategy/enrich.js:60-66`
  передаёт корректно.

**Effective premium.** Логика «Buy → ASK, Sell → BID, fallback → premium» реализована
**в четырёх независимых копиях**:
`optionPricing.js:182-203`, `futuresPricing.js:86-107`,
`metricsCalculator.js:28-49`, `hooks/usePositionExitCalculator.js:76-97`.

Копии **не идентичны**: в `optionPricing.js`/`futuresPricing.js` ручная премия имеет
**низший** приоритет (проверяется после bid/ask), в `metricsCalculator.js`/
`usePositionExitCalculator.js` — **высший**. Расхождение замаскировано тем, что все
живые вызовы предварительно строят `tempOption` с занулёнными `ask`/`bid`
(`PLChart.jsx:228-230,317-319,415-417,982-984`; `OptionsTableV3.jsx:202-207,1339-1346,1559-1564`;
`ExitPlanTable.jsx:508-513`; `ExitTimeDecayChart/utils/calculations.js:54-59`).
Паттерн соблюдён везде в живом коде, но это хрупко: любой новый вызов
`calculateOptionPLValue` без `tempOption` при включённой ручной премии молча возьмёт
ASK вместо введённого значения. **Рекомендация (не выполнять сейчас): свести к одной
функции `getEntryPrice` с явным приоритетом.**

**Пятая копия математики:** `components/CalculatorV2/CalculatorDealTabs/BinanceDealTab.jsx:17-54`
содержит собственный Black-Scholes (erf-аппроксимация Абрамовица-Стегана, `normCDF`,
`blackScholes`) **без** дивидендов, **без** пола по intrinsic, со своим полем ставки
(дефолт 3.7%, `:354`) и своим `T = (exp − scen)/86400/365` (`:478`).
Математика сама по себе верна, но это второй, несинхронизированный источник истины
для криптосделок.

`adjustPLByStockGroup` (`optionPricing.js:316-333`) — эмпирический фадж-фактор
(деление убытка на `down_mult`, умножение прибыли на `up_mult`), научного основания
не имеет. **В проде не активен:** `stockClassification` жёстко `null` во всех шести
местах передачи (`UniversalOptionsCalculator.jsx:4346,4678,4877,4954,5051,5077`).
Спящий код, на цифры сейчас не влияет.

## 7. Численная устойчивость и точность на хвостах

`normalCDF` (`blackScholes.js:12-17`, дубль в `black76.js:25-30`) — Abramowitz-Stegun
26.2.17 (Zelen–Severo, 5 членов). Измеренная точность против эталона Hart:

| d | приближение | эталон | абс. ошибка | отн. ошибка |
|---|---|---|---|---|
| −2 | 2.275006e−2 | 2.275013e−2 | −7.3e−8 | 0.0003% |
| −3 | 1.349967e−3 | 1.349898e−3 | 6.9e−8 | **0.0051%** |
| −3.5 | 2.326734e−4 | 2.326291e−4 | 4.4e−8 | **0.019%** |
| −4 | 3.168603e−5 | 3.167124e−5 | 1.5e−8 | **0.047%** |
| −4.5 | 3.400803e−6 | 3.397673e−6 | 3.1e−9 | 0.092% |
| −5 | 2.871050e−7 | 2.866516e−7 | 4.5e−10 | 0.158% |
| 0 | 0.4999999 | 0.5 | −1.5e−7 | — |

Абсолютная ошибка ограничена **7.5e−8** во всём диапазоне — это гарантия метода,
и именно абсолютная ошибка, а не относительная, определяет ошибку цены
(цена входит как `S·N(d1) − K·e^(−rT)·N(d2)`).

Перевод в деньги (на 1 контракт):

| Сделка | d1 | ошибка цены |
|---|---|---|
| AAPL OTM call 60д (S=230,K=260,σ=28%) | −0.96 | **$0.0011** |
| дальний OTM put 45д (S=500,K=420,σ=30%) | +1.76 | **$0.0015** |
| очень дальний OTM call 30д (S=100,K=130,σ=35%) | −2.53 | **$0.0003** |
| ATM call 90д | +0.15 | **$0.0001** |

**Вывод: хвосты не проблема.** Даже при d ≈ −4 ошибка в цене опциона < $0.01 на
контракт — на пять-шесть порядков меньше наблюдаемой медианы $20. Замена на erf/Hart
математически ничего не даст.

Прочая устойчивость:
* `calculateOptionPrice` клампит `σ ≥ 0.01`, `S,K ≥ 0.01`, `q ≥ 0` (`blackScholes.js:74-77`) — ОК.
* `calculateGreeks` (`blackScholes.js:104`) **не** клампит σ: при σ=0
  `calculateD1D2` вернёт `{0,0}`, и `gamma = n(0)/(S·0·√T) = Infinity`.
  На цены не влияет (греки идут отдельной веткой), но NaN/Infinity может утечь в UI.
* `calculateD1D2` при `T≤0` или `σ≤0` возвращает `{d1:0, d2:0}`, что дало бы
  бессмысленную цену `0.5·(S·e^(−qT) − K·e^(−rT))`. Защищено внешними guard'ами в
  `calculateOptionPrice`, но контракт функции сам по себе небезопасен.
* `normalCDF(0)` = 0.4999999 (недобор 1.5e−7) → невязка пут-колл паритета
  ≈ $0.0065 на контракт. Пренебрежимо.

## Вердикт

**Соответствует науке; отклонения незначительны для акционного профиля.**

Формулы BSM, Мертона и Black-76 воспроизведены без единой ошибки — паритет
выполняется до машинной точности, греки каноничны, конвенция времени правильная,
единицы IV и множители в живом пути согласованы, численная точность на хвостах
избыточна для задачи. Наблюдаемая медиана расхождения ~$20 объясняется
конвенцией дня экспирации + американской премией по путам, и это близко к
теоретическому минимуму для европейской модели.

**Единственное существенное отклонение — крипторежим:** `r = 0` вместо форвардного
базиса даёт систематическую недооценку коллов на 5–10% премии. Это не «тонкое»
отклонение, а концептуальная ошибка, и в криптосделках она будет доминировать над
всеми остальными эффектами.

Второй по значимости управляемый рычаг — **дивидендная доходность**: при
выключенном тумблере или пустом `q` ошибка на дивидендных акциях в 3–6 раз
превышает американскую поправку.
