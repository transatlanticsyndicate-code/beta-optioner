## ВАЖНО: направление эффекта — P&L растёт, а не падает

Изначальное ожидание (см. задачу) было «переход на 16:00 ET немного УМЕНЬШАЕТ
время до экспирации → P&L чуть более отрицательная». Фактический эффект —
**противоположный: dte увеличивается на ~0.83–0.875 дня, P&L для купленных
опционов чуть РАСТЁТ** (портфель: −$34 480 → −$33 155, то есть +$1 325 / +3.84%).

Причина расхождения с ожиданием — в арифметике самого сравнения. Старый расчёт
считал дни до **полуночи UTC дня экспирации** (00:00 UTC). В Нью-Йорке это —
**19:00–20:00 предыдущего календарного дня** (NY отстаёт от UTC на 4–5 часов),
то есть старый «нулевой» момент наступал почти на сутки РАНЬШЕ, чем реальное
закрытие рынка (16:00 ET того же дня экспирации = 20:00–21:00 UTC). Новый расчёт
двигает точку экспирации на эти недостающие ~20–21 час ПОЗЖЕ — время до
экспирации не сокращается, а корректно увеличивается почти на сутки относительно
прежнего (заниженного) значения. Для купленных (long) опционов больше времени до
экспирации ⇒ больше временной стоимости ⇒ P&L чуть выше (менее отрицательная).
Проверено напрямую на продовом коде (`node`, вызов реальных функций из
`frontend/src/utils/dateUtils.js`):

```
opt = { date: '2026-11-20', entryDate: '2026-07-30' }
calculateDaysRemainingUTC(opt, 0, 30, null)        → 113        (старая, целая)
calculateDaysRemainingPreciseET(opt, 0, 30, null)  → 113.875    (новая, точная ET)
getExpirationMomentET('2026-11-20')                → 2026-11-20T21:00:00.000Z (16:00 ET = 21:00 UTC, EST)
```

Направление и однородность эффекта:
- 128 из 132 ног — рост P&L (после > до), 0 — падение, 4 — без изменений
  (зафиксированные/locked-позиции: `initialDaysToExpiration` заморожен при
  сохранении и ET-поправка на них не распространяется — так и задумано, см.
  `dateUtils.js`).
- Средний сдвиг dte по незамороженным ногам: **+0.8363 дня** (в диапазоне
  0.833 — лето/EDT, 0.875 — зима/EST, в зависимости от даты экспирации).
- Для каждой ноги ΔP&L (колонка «с якорем») в точности равна ΔTheo (без якоря) —
  это ожидаемо: точка якоря Fact P&L считается через неизменённый
