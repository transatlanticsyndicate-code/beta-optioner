# Handoff: MAX убыток с поддержкой положительного флора

**Источник:** beta.optioner.online (старый калькулятор, CalculatorV2)
**Назначение:** calc.optioner.online (переписка с нуля)
**Актуально на:** 2026-05-06

---

## 1. Зачем

Метрика «MAX убыток» описывает **худший P&L стратегии на дату экспирации**. У большинства стратегий это число отрицательное (реальный убыток), но у части стратегий — например, у коллара (long stock + buy put + sell call) или у вертикального дебетного спреда с подходящим net premium — `min(P&L)` на экспирации **положителен**: даже в худшем сценарии стратегия гарантированно не уходит в минус, и в этой точке `min(P&L) ≥ 0`.

Старый калькулятор такой случай не показывал: при `maxLoss ≥ 0` поле «MAX убыток» рисовалось прочерком («—»), а в блоке «Базовый актив» из значения брался модуль и слева добавлялся литеральный минус — пользователь видел красное «−$96» вместо реального «+$96». Это вводит в заблуждение: пользователь не понимает, что построил стратегию с гарантированным мин-профитом.

---

## 2. Корень

Двойственная природа «MAX убыток»:

- Семантически это **«худший P&L»**, и его значение — просто `min(P&L)` по диапазону цен на экспирации.
- Визуально проектировалось как «всегда красное число с минусом», что верно только для чисто-отрицательных стратегий.

В двух местах кода эта двойственность проявляется по-разному:

- В шапке метрик калькулятора: условие `maxLoss < 0 ? formatCurrency(maxLoss) : '—'` — положительный флор вообще не показывался.
- В блоке «Базовый актив»: значение бралось через `Math.abs(plMetrics.maxLoss)` и в JSX печаталось как `'−$ ' + value` — знак терялся, а минус становился литеральной строкой.

Дополнительная техническая ловушка: при пустом массиве P&L `Math.min(...[]) = +Infinity` и `Math.max(...[]) = -Infinity`, и эти значения утекали в UI. Без отдельной защиты пустые данные ломали отображение.

---

## 3. Решение

### 3.1. Метрика

`min(P&L)` на дату экспирации возвращается **со знаком**, как есть. Никаких `Math.abs` в селекторе. Если массив P&L пустой — fallback на `0`, чтобы не утекало `±Infinity`.

```
const sourceArr = expirationPLArray.length > 0 ? expirationPLArray : totalPLArray;
maxProfit = sourceArr.length > 0 ? Math.max(...sourceArr) : 0;
maxLoss   = sourceArr.length > 0 ? Math.min(...sourceArr) : 0;
```

### 3.2. Шапка метрик

Метрика всегда показывает `formatCurrency(maxLoss)`, когда есть полные опционы. Цвет — динамический по знаку:

| `maxLoss` | Цвет | Знак | Семантика |
|---|---|---|---|
| `< 0` | красный | `−$N` | реальный максимальный убыток |
| `> 0` | зелёный | `+$N` | гарантированный минимальный профит на экспирации |
| `= 0` | серый | `$0` | break-even (ровно ноль в худшей точке) |

Тултип: «Худший P&L стратегии НА ДАТУ ЭКСПИРАЦИИ. Отрицательное — максимальный убыток. Положительное — гарантированный мин-профит (стратегия не может уйти в минус)».

### 3.3. Блок «Базовый актив»

Значение в этом блоке тоже хранится **со знаком**. Логика лимита убытка («плашка ПРЕВЫШЕНИЕ / В РАМКАХ ЛИМИТА») использует **отдельную переменную «экспозиция к убытку»**:

```
lossExposure = maxLoss < 0 ? Math.abs(maxLoss) : 0
```

Это единственное место, где модуль уместен: лимит «потерь» нарушается только когда есть реальный убыток. Если `maxLoss ≥ 0`, фактической экспозиции к убытку нет и плашка лимита всегда «в рамках».

В JSX знак и цвет вычисляются в одной точке:

```
<span className={maxLoss < 0 ? 'text-red-600' : maxLoss > 0 ? 'text-green-600' : 'text-gray-500'}>
  {maxLoss < 0 ? '-' : maxLoss > 0 ? '+' : ''}$ {formatNumber(Math.abs(maxLoss))}
</span>
```

### 3.4. Risk/Reward

Эту метрику переделывать не пришлось — старый код уже корректно возвращает `'∞'` для `maxProfit > 0 && maxLoss >= 0`. Это и был сигнал, что вычисление само по себе верное, и проблема — только в отображении.

## 4. Сценарии для тестирования

| # | Стратегия | Ожидание |
|---|---|---|
| Q1 | Голый Buy Call | MAX убыток < 0, красный, со знаком «−». Risk/Reward — реальное число. |
| Q2 | Коллар (long 200 BLDR + Buy PUT 95×2 + Sell CALL 110×2) с net-кредитом, гарантирующим положительный флор | MAX убыток > 0, зелёный, со знаком «+». Risk/Reward = ∞. В блоке «Базовый актив» MAX убыток показывает то же значение зелёным. |
| Q3 | Дебетный спред в точке зеро-ноль | MAX убыток = $0, серый. |
| Q4 | Стратегия без опционов / без полных параметров | MAX убыток показывает прочерк («—»), цвет нейтральный. |

Также проверить, что плашка «лимит превышен» в блоке «Базовый актив» **не загорается** для стратегий из Q2 и Q3 — там `lossExposure = 0`.

## 5. Чек-лист переноса в новый калькулятор

- [ ] Селектор метрики возвращает `min/max` **со знаком**, без `Math.abs`.
- [ ] Защита от пустых массивов: `sourceArr.length > 0 ? Math.min(...sourceArr) : 0`. Аналогично для `Math.max`.
- [ ] В UI «MAX убыток» цвет берётся из знака значения: `< 0` → красный, `> 0` → зелёный, `= 0` → серый. Никакого захардкоженного «всегда красный».
- [ ] Знак в строке: либо через `formatCurrency(value, { signed: true })`, либо через тернарник в JSX (как в §3.3) — главное, что для `> 0` показывается явный «+», а не «−».
- [ ] Для логики лимита убытков ввести **отдельную** переменную `lossExposure = max(0, -maxLoss)`. Лимит превышается только когда `lossExposure > limit`.
- [ ] Тултипы метрики обновить: явно сказать про положительный флор (стратегии с гарантированным мин-профитом).
- [ ] Не показывать прочерк («—») у MAX убытка только из-за того, что значение неотрицательное — это потеря информации.

## 6. Открытые вопросы для нового проекта

1. **Семантически правильнее ли переименовать метрику** в «MAX P&L на экспирации» или «Худший P&L»? «MAX убыток» — устоявшийся, но семантически неточный термин для стратегий с положительным флором. В старом проекте оставлено как есть (минимум изменений UX), в новом стоит обсудить.
2. **Точка безубытка (Breakeven)** для стратегий с положительным флором не существует (P&L никогда не пересекает ноль). Сейчас в этом случае показывается прочерк — это корректно. Стоит добавить тултип, объясняющий, что у этой стратегии нет точки безубытка, потому что она целиком в плюсе.
3. **Range MAX убытка**: сейчас расчёт идёт по диапазону цен `[currentPrice × 0, currentPrice × 2]`. Для стратегий с теоретически бесконечным убытком (голые short call/put) это даёт усечённый ответ, и в текущем тултипе явно про это сказано. Если в новом проекте такие стратегии выделять отдельно — стоит предусмотреть пометку «− ∞» вместо числа, аналогично «∞» у MAX прибыли.
