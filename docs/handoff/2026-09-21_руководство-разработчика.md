## 1. Что это за продукт

Платформа для работы с опционами: калькулятор конструкций, ИИ-подбор сделок, учёт позиций.
Пользуется ей заказчик и узкий круг людей — это не массовый публичный сервис. Заказчик
находится в Панаме и торгует **только на биржах США** (это важно для логики определения биржи).

История, которую полезно знать. Приложение росло полгода итерациями и накопило ~33 000 строк
без единого теста, поэтому в какой-то момент была начата полная переписка калькулятора с нуля
в отдельном репозитории — с тестами, архитектурными решениями (ADR) и строгим CI. Переписку
**остановили**: разработка основного приложения к тому времени была завершена, оно работает
стабильно, и переписывать стало нечего. Сейчас продукт в режиме поддержки — правки по запросу
заказчика и исправление ошибок, а не развитие с нуля.

### 5.2. Установка и запуск локально

```bash

# бэкенд
```

Положить `backend/.env`. Минимум для локальной работы:

Запуск — два терминала:


```bash

```

Фронт сам проксирует `/api` на `localhost:8000` (настройка `proxy` в `frontend/package.json`).

### 5.3. Деплой

```bash
./scripts/deploy_local.sh       # фронт + бэк + рестарт PM2
./scripts/deploy_crypto.sh      # только crypto (статика)
```

Скрипт собирает фронт, заливает `frontend/build`, заливает исходники бэкенда, доставляет
зависимости, перезапускает PM2, делает smoke-тест.

> ⚠️ **Ложная тревога в конце деплоя.** Smoke-тест дёргает `/api/health`, которого не
> существует, и всегда печатает ошибку HTTP. Это **не сбой деплоя**. Проверяйте результат,
> открыв https://beta.optioner.online в браузере.

> ⚠️ **rsync идёт с `--delete`** — сервер зеркалится под ваше локальное дерево. Деплоить можно
> только из ветки, где есть **всё**, что сейчас на проде. Деплой из отставшей ветки удалит
> чужие изменения на сервере. Это уже случалось.

> ⚠️ Скрипт намеренно исключает `*.db` из заливки. Никогда не убирайте это исключение — иначе
> локальная пустая база затрёт боевые сделки.

### 5.4. База и бэкапы

## 6. Проект Б — calc.optioner.online (остановлен)

### 6.1. Что это было и почему закрыто

Полная переписка калькулятора с чистого листа: своя архитектура, свой бэкенд, своя база,
своё расширение Chrome, ничего из основного проекта не переиспользуется (ADR-023).

**Разработка остановлена.** Причина: разработка основного приложения завершена, оно
демонстрирует стабильную работу — переписка потеряла смысл.

Что осталось: репозиторий, задеплоенный сайт `calc.optioner.online`, бэкенд на сервере как
systemd-сервис и около 380 зелёных юнит-тестов. Всё это — **архив**. Развивать не нужно,
задач по нему нет.

Разделы 6.2–6.5 ниже оставлены справочно — на случай, если заказчик когда-нибудь решит
вернуться к переписке или потребуется что-то достать из этого кода. Для повседневной работы
они не нужны.

> Решить с заказчиком: оставить `calc.optioner.online` работать как есть или выключить сервис
> и освободить сервер. Пока ничего не трогаем — сайт живой.

### 6.2. Стек и правила

- Фронтенд: **React + Vite + TypeScript**, Tailwind + shadcn/ui, только тёмная тема,
  фиксированная ширина 1920px, мобильные не поддерживаются.
- Бэкенд: **FastAPI + SQLAlchemy 2.0 + Pydantic v2**, JWT-авторизация, SQLite.
  Порт 8003, systemd-сервис `calc-backend.service`.
- Расширение Chrome: папка `extension/` (Optioner Calc Buttons).

Жёсткие правила проекта (нарушение блокирует CI):
- максимум **250 строк** на файл;
- запрещены файлы с суффиксами `-old`, `-v2`, `-legacy`, `.backup`, `.bak`;
- запрещён закомментированный код;
- комментарии только «почему», не «как»;
- юнит-тесты обязательны для всех расчётных функций;
- каждая папка модуля обязана иметь `README.md`.

**Все архитектурные решения — 27 ADR в `docs/decisions/`.** Отклоняться от них нельзя без
явного обсуждения с заказчиком и замены соответствующего ADR. Прочитайте их до первой правки.

> ⚠️ `CLAUDE.md` этого репозитория ссылается на плановый документ
> `~/.claude/plans/dapper-squishing-hartmanis.md`. **Этого файла на машине нет** — он жил в
> личной папке прежнего сотрудника. Либо запросите его, либо считайте источником правды
> `CHANGELOG.md` + `docs/decisions/` + `docs/architecture.md`.

## 8. Расширения Chrome

Ставятся **распакованными**: `chrome://extensions` → «Режим разработчика» → «Загрузить
распакованное расширение». В Chrome Web Store их нет и публиковать не планировалось.

| Где лежит | Что делает | Версия |
|---|---|---|
| `beta.../EXTENTIONS/OptionsCPbuttons` | тянет опционную доску с TradingView в старый калькулятор | 1.7.2 |
| `beta.../EXTENTIONS/binance_parser` | тянет крипто-доску с Binance через публичный API | 2.2.0 |
| `beta.../EXTENTIONS/IBKR_Bridge` | мост к терминалу IBKR | — |
| `calc.../extension` | то же для нового калькулятора | 0.3.2 |

**Правило:** при любой правке расширения поднимать версию в его `manifest.json` — заказчик и
коллеги отличают сборки только по номеру версии. Патч при багфиксах, minor при новых функциях.

Без расширения основной сценарий работы не воспроизводится: доска опционов приходит в
калькулятор именно оттуда.

## 10. Правила работы

### Ветки и деплой (обязательно)

Это не бюрократия: параллельные сессии уже затирали деплои друг друга.

1. В начале работы: `git fetch origin && git rebase origin/main`.
2. Перед деплоем — то же самое ещё раз.
3. После успешного деплоя и подтверждения заказчика, что всё работает — влить ветку в `main`
   (fast-forward), запушить `main`, удалить ветку локально и на origin.
4. Никогда не деплоить из ветки, отставшей от `origin/main`.

Подробно с примерами: `docs/handoff/parallel-sessions-process.md`.

### CI

**Старый репозиторий.** В нём есть workflow «Deploy to Beta Server», который срабатывает на
push в `main` и **падает на каждом пуше** (нет секретов). Деплой им не идёт и идти не должен —
только скриптом. Workflow стоит либо починить, либо отключить; пока он просто шумит.
Проверка «Check File Size Limit» (300 строк) тоже регулярно красная — в старом проекте лимит
фактически не соблюдается. Husky-хук pre-commit сломан, поэтому коммиты делаются с `--no-verify`.

**Новый репозиторий.** CI живой и его требования соблюдаются. Перед пушем прогоняйте
`npm run check:all` и тесты.

### Формат коммитов

```
type(scope): краткое описание
```

Типы: `feat`, `fix`, `refactor`, `hotfix`, `docs`, `test`, `chore`.

### Общение с заказчиком

Заказчик — не программист. В отчётах не показывать код, не называть файлы и функции.
Рапортовать на уровне логики: что изменилось, какой эффект, как проверено. Язык — русский.
Когда есть развилка — 2–3 варианта с последствиями и рекомендация.

## 13. Грабли, на которые уже наступали

1. **Классический «Север»** (математическая стратегия) в старом калькуляторе — отключённый
   мёртвый код, кнопка скрыта. Не чинить, не развивать. Живая версия — «Север GPT» через OpenAI.
2. **ИИ-подбор асинхронный**: модель думает 2–4 минуты, ответ забирается опросом. Синхронно
   держать нельзя — прокси отвалится.
3. **Режим двойной экспирации тратит вдвое больше денег** на OpenAI за один запуск.
4. **ИИ-подбору дают готовые числа P&L** по каждому страйку — модель не умеет оценивать
   опционы «в уме». Это ключевое решение для точности, не убирать.
5. **Биржу для американских тикеров берём из symbol-search расширения**, а не из голого
   символа: голый символ TradingView резолвится по региону пользователя.
6. **Потеря данных в крипте (июнь 2026):** молчаливый `catch` на сохранении плюс перезапись
   локальных данных облачными. Урок: любое сохранение должно показывать статус, а миграции
   офлайн-first приложений — сверять даты записей, а не доверять «облачной копии».
7. **Экран «ИИ-подбор / SuperSelection / Magic / Golden»** в старом калькуляторе — мёртвый код.
8. **Лимит 300 строк** в старом проекте формально включён в CI, но фактически не соблюдается.
   В новом проекте лимит 250 строк соблюдается строго.
