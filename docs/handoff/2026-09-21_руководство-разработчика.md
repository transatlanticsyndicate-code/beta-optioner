## 1. Что это за продукт

Платформа для работы с опционами: калькулятор конструкций, ИИ-подбор сделок, учёт позиций.
Пользуется ей заказчик и узкий круг людей — это не массовый публичный сервис. Заказчик
находится в Панаме и торгует **только на биржах США** (это важно для логики определения биржи).

Данные по опционам приходят **из браузерного расширения**, которое снимает доску с
TradingView, а не из платных биржевых API. Это ключевая особенность архитектуры: без
установленного расширения основной сценарий работы не воспроизводится (раздел 7).

## 5. Приложение

### 5.1. Из чего состоит

- `frontend/` — React 18 на `react-scripts` (Create React App), JS/JSX, Tailwind, Radix UI,
  ag-grid, plotly, lightweight-charts.
- `backend/` — FastAPI + SQLAlchemy + uvicorn. На сервере под PM2, порт 8002, наружу через
  nginx как `/api/`.
- `crypto/` — отдельное приложение на Vite + TypeScript (без React) для crypto.optioner.online.
  Состояние хранит в том же бэкенде (префикс `/crypto`).
- `EXTENTIONS/` — расширения Chrome (раздел 7).
- `MODEL/` — ONNX-модель.

**База — SQLite-файл**, не PostgreSQL: `backend/beta_options_analyzer.db` на сервере,
`backend/dev_options_analyzer.db` локально. `CLAUDE.md` и часть старых доков утверждают
PostgreSQL — это неверно, PostgreSQL на сервере пустой и не используется.

Карта кода:

| Путь | Что |
|---|---|
| `frontend/src/pages/UniversalOptionsCalculator.jsx` | главный экран |
| `frontend/src/components/CalculatorV2/` | компоненты калькулятора |
| `frontend/src/utils/` | расчётная математика (P&L, IV, ценообразование) |
| `backend/app/routers/` | endpoint'ы API, по файлу на тему |
| `backend/app/services/` | бизнес-логика и клиенты внешних API |

### 5.2. Установка и запуск локально

```bash
cd ~/Desktop/WINDSURF/beta.optioner.online

# фронтенд
cd frontend && npm install && cd ..

# бэкенд
cd backend
python3.10 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

Положить `backend/.env`. Минимум для локальной работы:

```
ENVIRONMENT=development
PORT=8000
DATABASE_URL=sqlite:///./dev_options_analyzer.db
ALLOWED_ORIGINS=http://localhost:3000,http://localhost:3001
AI_PROVIDER=gemini
```

Плюс те платные ключи из раздела 8, функциональность которых будете проверять. Боевой `.env`
можно взять за основу, но **обязательно поменяйте `ENVIRONMENT`, `PORT` и `DATABASE_URL`** на
локальные, иначе рискуете работать по боевым настройкам.

Запуск — два терминала:

```bash
cd backend && source venv/bin/activate
uvicorn app.main:app --reload --port 8000     # http://localhost:8000/docs
```

```bash
cd frontend && npm start                       # http://localhost:3000
```

Фронт сам проксирует `/api` на `localhost:8000` (настройка `proxy` в `frontend/package.json`).

### 5.3. Деплой

```bash
./scripts/deploy_local.sh       # фронт + бэк + рестарт PM2
./scripts/deploy_crypto.sh      # только crypto (статика)
```

Скрипт собирает фронт, заливает `frontend/build`, заливает исходники бэкенда, доставляет
зависимости, перезапускает PM2, делает smoke-тест.

> ⚠️ **Ложная тревога в конце деплоя.** Smoke-тест дёргает `/api/health`, которого не
> существует, и всегда печатает ошибку HTTP. Это **не сбой деплоя**. Проверяйте результат,
> открыв https://beta.optioner.online в браузере.

> ⚠️ **rsync идёт с `--delete`** — сервер зеркалится под ваше локальное дерево. Деплоить можно
> только из ветки, где есть **всё**, что сейчас на проде. Деплой из отставшей ветки удалит
> чужие изменения на сервере. Это уже случалось.

> ⚠️ Скрипт намеренно исключает `*.db` из заливки. Никогда не убирайте это исключение — иначе
> локальная пустая база затрёт боевые сделки.

### 5.4. База и бэкапы

- Боевая база: `/var/www/beta/backend/beta_options_analyzer.db` (SQLite, ~10 таблиц).
- Ежедневный бэкап: cron в 03:30 → `/root/scripts/backup_beta_db.sh` → копии в

## 9. Правила работы

### Ветки и деплой (обязательно)

Это не бюрократия: параллельные сессии уже затирали деплои друг друга.

1. В начале работы: `git fetch origin && git rebase origin/main`.
2. Перед деплоем — то же самое ещё раз.
3. После успешного деплоя и подтверждения заказчика, что всё работает — влить ветку в `main`
   (fast-forward), запушить `main`, удалить ветку локально и на origin.
4. Никогда не деплоить из ветки, отставшей от `origin/main`.

Подробно с примерами: `docs/handoff/parallel-sessions-process.md`.

### CI

В репозитории есть workflow «Deploy to Beta Server», который срабатывает на push в `main` и
**падает на каждом пуше** (нет секретов). Деплой им не идёт и идти не должен — только
скриптом. Workflow стоит либо починить, либо отключить; пока он просто шумит.

Проверка «Check File Size Limit» (300 строк на файл) тоже регулярно красная — в этом проекте
лимит фактически не соблюдается. Husky-хук pre-commit сломан, поэтому коммиты делаются
с `--no-verify`.

### Формат коммитов

```
type(scope): краткое описание
```

Типы: `feat`, `fix`, `refactor`, `hotfix`, `docs`, `test`, `chore`.

### Общение с заказчиком

Заказчик — не программист. В отчётах не показывать код, не называть файлы и функции.
Рапортовать на уровне логики: что изменилось, какой эффект, как проверено. Язык — русский.
Когда есть развилка — 2–3 варианта с последствиями и рекомендация.

## 12. Грабли, на которые уже наступали

1. **Классический «Север»** (математическая стратегия) — отключённый мёртвый код, кнопка
   скрыта. Не чинить, не развивать. Живая версия — «Север GPT» через OpenAI.
2. **ИИ-подбор асинхронный**: модель думает 2–4 минуты, ответ забирается опросом. Синхронно
   держать нельзя — прокси отвалится.
3. **Режим двойной экспирации тратит вдвое больше денег** на OpenAI за один запуск.
4. **ИИ-подбору дают готовые числа P&L** по каждому страйку — модель не умеет оценивать
   опционы «в уме». Это ключевое решение для точности, не убирать.
5. **Биржу для американских тикеров берём из symbol-search расширения**, а не из голого
   символа: голый символ TradingView резолвится по региону пользователя.
6. **Потеря данных в крипте (июнь 2026):** молчаливый `catch` на сохранении плюс перезапись
   локальных данных облачными. Урок: любое сохранение должно показывать статус, а миграции
   офлайн-first приложений — сверять даты записей, а не доверять «облачной копии».
7. **Экран «ИИ-подбор / SuperSelection / Magic / Golden»** — мёртвый код.
8. **Лимит 300 строк на файл** формально включён в CI, но фактически не соблюдается.
