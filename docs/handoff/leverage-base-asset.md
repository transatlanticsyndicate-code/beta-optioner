# Плечо для базового актива — спецификация для нового калькулятора

**Источник:** beta.optioner.online (старый калькулятор, CalculatorV2)
**Дата фиксации поведения:** 2026-05-01
**Передача в:** calc.optioner.online (переписка с нуля)
**Статус в старом проекте:** реализовано и задеплоено в продакшен
**Связанный handoff:** `signed-amounts-base-asset-block.md` (контракт строк со знаками)

---

## 1. Зачем

В блоке «Базовый актив» строка «Стоимость позиций» считалась по полной нотинальной стоимости акций (`Σ sign × |qty × entry|`). Для маржинального счёта это даёт завышенный результат: при покупке/шорте акций брокер блокирует только часть стоимости (для большинства брокеров — `notional / 4` при стандартной марже), а остальное даёт «в долг» под обеспечение портфеля.

В результате:
- «Стоимость позиций» показывала больше денег, чем реально блокируется на счёте.
- «Итого» (`positionsCost + optionsCost`) переоценивало нагрузку на капитал.
- Плашка лимита на инструмент срабатывала «ПРЕВЫШЕНИЕ» там, где по факту в рамках лимита.

Решение: пользовательская настройка «Плечо для базового актива». Стоимость позиций по БА делится на это плечо. Опционная премия не делится — её платят/получают полностью. P&L и MAX-убыток не делятся — это финансовый результат, не капитал при входе.

---

## 2. Семантика

| Понятие | Значение | Применение |
|---|---|---|
| Плечо `N` | Множитель маржинальности счёта (целое или дробное число `>= 1`) | Глобальная пользовательская настройка |
| Маржа БА | `notional / N` | То, что реально блокируется на счёте при открытии позиции |
| Дефолт | `4` | Соответствует стандартной марже у большинства брокеров (25%) |

Плечо — это «характеристика моего счёта», не часть конкретной опционной конструкции. При загрузке любой сохранённой стратегии плечо берётся из текущего значения настройки, не из сохранения.

LONG и SHORT по БА делятся на плечо **симметрично**. Reg T требует ~150% маржи на шорт акций (что строже плеча 4), но мы сознательно используем то же плечо для шорта — упрощение, согласованное с продакт-овнером. Если пользователь хочет точнее — он понижает значение плеча.

---

## 3. Формулы

### 3.1. Стоимость позиций БА

```
positionsCost = Σ ( sign(pos) × |quantity × entryPrice| ) / leverage

где sign(pos) =  −1, если позиция LONG
                +1, если позиция SHORT
    leverage  >= 1
```

При `leverage = 1` формула эквивалентна старой (без плеча).

### 3.2. Опционная премия — НЕ делится

```
optionsCost = Σ ( sign(opt) × |quantity| × entryPremium × contractMultiplier )
```

Плечо к опционной премии **не применяется**. Премия уплачивается/получается в полном объёме при открытии позиции.

### 3.3. Итого

```
totalCost = positionsCost + optionsCost
```

`positionsCost` уже делён на плечо, поэтому `totalCost` отражает реальный нетто-кеш-флоу с учётом маржи.

### 3.4. Лимит на инструмент

```
usedCapital = max(0, −totalCost)
exceeded = (limit > 0) && (usedCapital > limit)
```

Логика проверки лимита **не меняется** — но `totalCost` теперь после плеча, поэтому лимит сравнивается с реальной блокировкой капитала.

### 3.5. Что НЕ делится на плечо

- **Опционная премия** (см. §3.2).
- **P&L базового актива** — это финансовый результат, цены движутся в долларах одинаково независимо от плеча.
- **P&L TOTAL** — то же самое.
- **MAX убыток** — это наихудший P&L, не блокировка капитала.
- **Маржинальные требования по шорт-опционам** — отдельная метрика, не входит в `optionsCost` (см. `signed-amounts-base-asset-block.md` §3.2).

## 4. Хранение и инициализация

| Параметр | Значение |
|---|---|
| Где хранится | `localStorage` |
| Ключ | `baseAssetLeverage` |
| Формат | строка-число (`String(N)`) |
| Дефолт при отсутствии ключа | `4` |
| Валидация при чтении | `parseFloat`, проверка `Number.isFinite && >= 1`; иначе `4` |
| Защита в компоненте | `effectiveLeverage = (typeof === 'number' && finite && >= 1) ? leverage : 1` |

В сохранённых конфигурациях стратегий плечо **не сохраняется**. Это намеренно: плечо — настройка счёта, не часть стратегии. При загрузке любой стратегии используется текущее значение из localStorage.

В Chrome-расширении (передача данных позиций в калькулятор) плечо **не используется и не передаётся**. Расширение шлёт сырые `quantity`, `entryPrice` — деление на плечо происходит только в калькуляторе при отображении.

## 5. UI

### 5.1. Поле настройки

**Местоположение:** панель «Настройки калькулятора», между блоком «Учитывать дивиденды» и блоком «Безрисковая ставка».

**Контрол:** числовой input.

**Параметры:**
- `min = 1`
- `step = 0.5`
- `value` — текущее плечо (синхронизируется с внешним state при изменении)

**Поведение:**
- На каждый ввод символа — локальный «черновик» обновляется немедленно (чтобы пользователь мог стереть значение и набрать новое).
- Внешний state обновляется только когда черновик даёт валидное `>= 1`.
- При потере фокуса (`onBlur`) — если в черновике невалидное значение или `< 1`, принудительно проставляется `1`.

**Подпись:** «Плечо для базового актива» + мелкая подсказка «Делится на стоимость позиций БА. Премия опционов не делится».

**Видимость:** всегда (не зависит от `calculatorMode`). Фьючерсы тоже маржинальные.

### 5.2. Подпись строки в блоке «Базовый актив»

```
leverage > 1  →  «Стоимость позиций (плечо N)»
leverage = 1  →  «Стоимость позиций»  (как было до плеча)
```

`N` форматируется без хвостового `.0`: `4`, не `4.0`. JS-нативное `String(N)` это делает автоматом.

**Tooltip** (при `leverage > 1`): «Делится на плечо. Маржинальное требование, не полная стоимость акций».

### 5.3. Цвет и формат значения

Не меняются по сравнению с правилами в `signed-amounts-base-asset-block.md` §5: формат `+$ X` / `−$ X` / `$ 0`, нейтральный цвет для строк «Стоимость позиций» и «Затраты на опционы», цветной только «Итого».

## 6. Сценарии для тестирования

Полная стоимость акции `$100`, лот `100 шт`. Для всех сценариев `depositAmount = $5 000`, `instrumentCount = 1` → лимит на инструмент `$5 000`.

| # | Конструкция | Плечо | Стоимость позиций | Опционы | Итого | Лимит |
|---|---|---|---|---|---|---|
| L1 | LONG 100 @ $100 | 1 | −$ 10 000 | $ 0 | −$ 10 000 | ПРЕВЫШЕНИЕ 5 000 |
| L2 | LONG 100 @ $100 | 4 | −$ 2 500 | $ 0 | −$ 2 500 | В РАМКАХ |
| L3 | SHORT 100 @ $100 | 4 | +$ 2 500 | $ 0 | +$ 2 500 | В РАМКАХ |
| L4 | LONG 100 @ $100 + Sell 1 Call @ 5 | 4 | −$ 2 500 | +$ 500 | −$ 2 000 | В РАМКАХ |
| L5 | LONG 100 @ $100 + Buy 1 Put @ 3 | 4 | −$ 2 500 | −$ 300 | −$ 2 800 | В РАМКАХ |
| L6 | LONG 100 @ $100 | 2 | −$ 5 000 | $ 0 | −$ 5 000 | В РАМКАХ (на грани) |
| L7 | LONG 100 @ $100 | 1.5 | −$ 6 666.67 | $ 0 | −$ 6 666.67 | ПРЕВЫШЕНИЕ 1 666.67 |
| L8 | leverage = NaN / null / "" / 0 / отрицательное | — | как при 1 | — | — | как при 1 |
| L9 | leverage = очень большое (1e9) | 1e9 | ≈ −$ 0 | $ 0 | ≈ $ 0 | В РАМКАХ |

**Поведенческие сценарии:**
- Изменение плеча в Настройках **немедленно** пересчитывает «Стоимость позиций», «Итого» и состояние плашки лимита.
- Стирание поля плеча → `onBlur` → значение становится `1`, в инпуте `«1»`.
- Перезагрузка страницы — плечо сохраняется (localStorage).
- Сохранение конфигурации стратегии → изменение плеча → загрузка той же конфигурации → плечо **не откатывается** на старое.
- При плече 1 подпись строки идентична состоянию «без плеча» (для пользователей, у которых плечо им неактуально).

## 8. Открытые вопросы для нового проекта

1. **Per-инструмент плечо.** Сейчас плечо одно на все тикеры. У реальных брокеров (например, IBKR) плечо различается по классам активов: акции — 4, ETF — 4–7, фьючерсы — десятки. Если в новом проекте хочется честнее — нужна таблица плеч по символу или по `assetClass`. Это меняет UX (одно поле → таблица или per-symbol override).
2. **Плечо для опционов.** Сейчас опционная премия не делится. Но для шорт-опционов брокер реально требует маржу (Reg T, покрытые/непокрытые). Если когда-нибудь решим включать маржу шортов в `optionsCost` (см. §3.2 / §3.3 в `signed-amounts-base-asset-block.md`), тогда «плечо для опционов» — отдельный коэффициент. Сейчас явно вне scope.
3. **Перевод подписи.** Слово «плечо» в скобке — короткое, помещается. Если новый UI использует другой тон/локализацию (например, английский), подпись может быть `Cost of positions (4× leverage)` или `Cost of positions (margin 25%)`. Решение продакта.
4. **Связь с «Финансовым контролем».** Поля `depositAmount` и `instrumentCount` живут в компоненте `FinancialControl` отдельно. Сейчас плечо живёт в `CalculatorSettings`. Если в новом проекте захочется собрать всё в один блок «Параметры счёта» — это организационное переименование, формулы не меняются.
5. **Точность отображения.** При дробном плече (например, 1.5) делёная сумма может стать дробной. Сейчас формат показывает целые доллары через `Math.round`. Можно округлять до сотых при дробных плечах — решение по UX.
