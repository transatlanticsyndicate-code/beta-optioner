# Инструкция для команды Андрея — интеграция sendPrIV_tocallc

## Что уже сделано (со стороны расширения)

Расширение twparser автоматически записывает в `localStorage` калькулятора команду
`sendPrIV_tocallc` каждый раз, когда на TradingView появляется оверлей сравнения.

Ключ: `tvc_refresh_command`
Формат команды:

```json
{
  "type": "sendPrIV_tocallc",
  "ticker": "AAPL",
  "boardUrl": "https://www.tradingview.com/options/chain/?symbol=AAPL&...",
  "currentPrice": 178.45,
  "options": [
    { "type": "C", "strike": 180, "date": "2026-06-18", "newIV": 32.5 },
    { "type": "P", "strike": 175, "date": "2026-06-18", "newIV": 28.1 }
  ],
  "timestamp": 1743600000000,
  "processed": false
}
```

**Важно:** в массив `options` попадают только опционы, для которых TV вернул реальное
значение IV. Опционы без данных (OTM, нет ликвидности) не включаются.

---

## Что нужно сделать в калькуляторе

### 1. Обработка команды sendPrIV_tocallc

В существующем polling-цикле `tvc_refresh_command` добавить обработку нового типа:

- Прочитать `currentPrice` → обновить цену underlying в интерфейсе
- Для каждого элемента `options[]`:
  - Найти строку по `(type, strike, date)`
  - Обновить поле Fact IV значением `newIV`
- После обработки поставить `processed: true`
- Опционально: записать результат в `tvc_refresh_result`

---

### 2. Кнопка «Обновить данные» (рекомендация)

**Проблема:** расширение записывает данные один раз — в момент открытия оверлея.
Если пользователь хочет получить свежие данные позже (без перезапуска всего процесса) —
нужна кнопка, которая инициирует повторный сбор.

**Рекомендуем добавить в калькулятор кнопку «Обновить данные».**

#### Что кнопка должна делать:

1. Записать в `localStorage` калькулятора команду-запрос:

```json
{
  "type": "requestRefresh",
  "ticker": "AAPL",
  "timestamp": 1743600000000
}
```

Ключ: `tvc_calc_command` (или другой согласованный ключ — см. ниже)

2. Расширение, работающее в фоне, читает этот ключ по polling и инициирует новый цикл
   обновления: открывает (или переключает) вкладку TradingView на нужный URL,
   запускает парсинг Chain View, показывает оверлей, записывает новый `sendPrIV_tocallc`.

3. Калькулятор ждёт появления нового `sendPrIV_tocallc` и применяет данные.

#### Ключ для запроса обновления (для согласования)

Предлагаем использовать существующий паттерн и договориться с командой расширения
о ключе. Вариант: `tvc_refresh_command` с типом `requestRefresh` — тогда polling
уже настроен. Либо отдельный ключ `tvc_calc_command` чтобы не смешивать направления.

---

## Как инициируется сбор данных (текущий процесс)

Для понимания того, что должна запустить кнопка:

1. Пользователь открывает сохранённую конфигурацию на `optioner.online`
2. Расширение замечает открытие вкладки калькулятора
3. Расширение открывает TV с нужным URL (Options Chain для нужного тикера)
4. На TV автоматически запускается парсинг Chain View
5. Когда парсинг завершён — фоновый скрипт расширения формирует объект с ценой и IV
6. Перед показом оверлея сравнения — записывает `sendPrIV_tocallc` в localStorage калькулятора
7. Показывает оверлей на TV
8. Калькулятор читает команду и обновляет Fact IV

**Кнопка «Обновить данные» должна запустить шаги 3–8 повторно,**
не требуя от пользователя переоткрывать конфигурацию.
