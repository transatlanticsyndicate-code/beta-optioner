# fix-iv-projection-flat-fallback — 2026-07-25

## Что сломалось

При симуляции будущего (ползунки «дней прошло» / «целевая цена») калькулятор проецирует
подразумеваемую волатильность (IV) опциона на будущую дату. Для тикеров без калибровочных
параметров (OU-модель) включалась запасная эвристика «IV растёт по мере приближения к
экспирации» (рост множителя до +50% к базовой IV). Эвристика не подтверждается рынком для
дальних OTM-опционов и систематически завышала прогнозную стоимость купленных опционов —
то есть занижала прогнозный убыток.

Реальный кейс — сделка ADBE (dbConfig `52553518-4846-4c46-a64b-48ba98916637`): прогноз
колонки Start P&L показывал **−$2 259**, тогда как фактический результат позиции —
**−$3 224**. При плоской IV (без роста) расчёт даёт **−$3 061** — практически совпадение
с фактом.

## Корень проблемы

Файл `frontend/src/utils/volatilitySurface.js`, функция `getProjectedIV`, запасная ветка
(строки 219–224 до правки): при отсутствии `ouParams` формула
`growthFactor = 1 + 0.5 * (1 - 1/sqrt(timeRatio))` умножала базовую IV на коэффициент до 1.5,
не опираясь ни на страйк, монетность, тип опциона, ни на реальное рыночное поведение —
чистая догадка на случай отсутствия данных. Так как `ouParams` передаёт только один
потребитель (`usePositionExitCalculator.js`, и только для откалиброванных тикеров), эта
ветка отрабатывала в подавляющем большинстве расчётов приложения — ошибка проникала во все
колонки P&L, графики и подбор опционов «Север», а не в один редкий сценарий.

## Что изменено

- `frontend/src/utils/volatilitySurface.js` — запасная ветка `getProjectedIV` теперь
  возвращает базовую (входную) IV без изменений, вместо умножения на растущий коэффициент.
  Путь OU-модели (калиброванные тикеры) не тронут.
- `frontend/src/utils/__tests__/volatilitySurface.test.js` — новый юнит-тест, 4 кейса:
  1. без `ouParams` IV остаётся равной базовой (кейс ADBE, 71→27 дней);
  2. `manualIvOverride` тоже держится плоско;
  3. краевой случай (`simulatedDaysToExpiration >= currentDaysToExpiration`) — базовая IV
     без изменений;
  4. путь OU-модели не затронут фиксом (с `ouParams` результат уходит в сторону `iv_mean`,
     а не остаётся плоским и не равен базовой).

## Как проверить

1. Открыть сделку с `dbConfig = 52553518-4846-4c46-a64b-48ba98916637` (ADBE) в калькуляторе.
   Колонка Start P&L должна показывать значение ≈ **−$3 060** (было −$2 259).
2. Прогнать фронтенд-тесты: `cd frontend && CI=false npm test -- --watchAll=false`.
   Сьют `volatilitySurface.test.js` должен быть зелёным, регрессий в существующих сьютах
   (`northStrategy/analyzer`, `northStrategy/scoring`) быть не должно.
