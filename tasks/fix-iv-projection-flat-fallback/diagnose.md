# DIAGNOSE — fix-iv-projection-flat-fallback

Дата: 2026-07-25 · commit_start: `0c5456c` · ветка `fix/iv-projection-flat-fallback`

---

## Root cause

**Файл:** `frontend/src/utils/volatilitySurface.js`
**Функция:** `getProjectedIV` (объявлена на строке 180)
**Строки запасной ветки:** **219–224**

```
219  // FALLBACK: нет калибровочных данных — консервативная модель роста IV ...
222  const timeRatio = currentDaysToExpiration / Math.max(simulatedDaysToExpiration, 1);
223  const growthFactor = 1 + 0.5 * (1 - 1 / Math.sqrt(timeRatio));
224  return Math.min(baseIVDecimal * growthFactor, 3.0) * 100;
```

Это единственное место в **живом** коде, где IV умножается на коэффициент роста.

### Важное уточнение по структуре функции

Вопреки ожиданию «три пути», в текущем коде `getProjectedIV` имеет **только два** рабочих пути:

1. **OU-модель** (строки 197–217) — работает, если переданы `ouParams` (`iv_mean`, `iv_kappa`).
2. **FALLBACK-эвристика роста** (строки 219–224) — во всех остальных случаях.

Пути «интерполяция по реальной IV-поверхности» внутри `getProjectedIV` **нет**: параметр
`ivSurface` принимается, но нигде в теле функции не используется. Вспомогательная функция
`getTermStructureRatio` (строка 240) объявлена, но **никогда не вызывается**; экспортируемая
`interpolateIV` (строка 72) **не импортируется ни одним модулем приложения**. То есть
поверхность волатильности сейчас на прогноз IV не влияет вообще.

### Кто реально попадает в fallback

`ouParams` передаётся **ровно одним потребителем** — `frontend/src/hooks/usePositionExitCalculator.js`
(строки 136–137, из `stockClassification.iv_mean/iv_kappa`), и только если тикер откалиброван.
Все остальные вызовы `getOptionVolatility` передают на месте `ouParams` значение `null`.
Следовательно **подавляющее большинство расчётов в приложении идёт через эвристику роста**.

---

## Why it happens

1. Эвристика заявляет, что IV опциона обязана расти по мере приближения к экспирации.
   Это утверждение верно для отдельных сценариев (событийная премия, ATM перед отчётом),
   но **неверно как универсальное правило** — особенно для дальних OTM-страйков, где IV
   после спада ожиданий обычно стоит на месте или падает.
2. Формула зависит **только от отношения времени**, не от страйка, монетности, типа опциона
   и фактического поведения рынка. Никакого источника данных под ней нет — это чистая
   догадка на случай «данных нет».
3. Рост множителя ограничен сверху 1.5, но уже при обычном горизонте симуляции даёт
   +15…+25%. Для **купленных** опционов завышенная IV = завышенная теоретическая цена
   = заниженный убыток. Ошибка **односторонняя и систематическая**, она не усредняется.
4. Так как fallback срабатывает почти везде (см. выше), ошибка проникает во все колонки
   и графики, а не в один редкий сценарий.

Числовая проверка на кейсе ADBE: `timeRatio = 71 / 27 = 2.63`, `sqrt = 1.622`,
`growthFactor = 1 + 0.5 × (1 − 1/1.622) = 1.192`. IV входа 50% → прогноз 59.6%
при фактических рыночных ~46-49%.

## Reproduction steps

1. Открыть калькулятор (`/` или `/tools/universal-calculator`) и загрузить сохранённую
   конфигурацию ADBE — `dbConfig 52553518-4846-4c46-a64b-48ba98916637`.
2. Состав позиции: 3× CALL 275, 1× CALL 270, 2× PUT 205; дата входа 11.06.26,
   71 день до экспирации, IV входа по ногам ~49-51%.
3. Оставить ползунок на «сегодня»: прошло 44 дня, до экспирации остаётся 27 дней.
   Тикер ADBE не откалиброван → `ouParams = null` → включается запасная ветка.
4. Внутри `getProjectedIV` считается `timeRatio = 71 / 27 = 2.63` и множитель **×1.192**;
   прогнозная IV становится **~59-60%** вместо рыночных **~46-49%**.
5. Посмотреть колонку **Start P&L**: показывается **−$2 259**.
6. Сверить с фактом по рынку: реальный результат позиции **−$3 224**.
7. Контрольный расчёт с «плоской» IV (IV остаётся равной входной) даёт **−$3 061** —
   отклонение от факта в разы меньше, чем у текущей эвристики.

**Ожидаемое поведение после фикса:** в отсутствие `ouParams` прогнозная IV равна базовой
(входной или заданной вручную), Start P&L по этому кейсу становится ≈ −$3 061.

## Scope

### A. Файлы к правке (живой код)

| Файл | Что менять |
|---|---|
| `frontend/src/utils/volatilitySurface.js`, строки **219–224** (`getProjectedIV`) | Заменить множитель роста на нейтральное поведение: вернуть базовую IV без изменения. Комментарий-обоснование переписать на русском. |
| `frontend/src/utils/volatilitySurface.js`, строка **493** (`IV_SURFACE_CONFIG.MAX_IV_GROWTH_RATIO: 1.5`) | Константа обслуживала только удалённую эвристику. Не импортируется ни одним модулем — можно оставить как есть либо удалить вместе с формулой. Решение принять в фазе FIX. |

### B. Тесты

Юнит-тестов, закрепляющих текущую формулу роста, **в репозитории нет**. Проверено:

- Во фронтенде существует всего два тестовых файла:
  `frontend/src/utils/northStrategy/__tests__/analyzer.test.js` и
  `frontend/src/utils/northStrategy/__tests__/scoring.test.js`.
- `analyzer.test.js` (строка 26) целиком **мокает** модуль волатильности:
  `jest.mock('../../volatilitySurface', () => ({ getOptionVolatility: () => 0.3 }))`,
  поэтому от формулы не зависит и после фикса продолжит проходить без правок.
- В бэкенде расчёта IV-проекции нет (Black-Scholes считает только фронтенд),
  поиск по `growthFactor` / `timeRatio` в `backend/` не даёт совпадений.

**Вывод:** обновлять существующие тесты не требуется. При желании в фазе FIX можно
добавить новый тест на `getProjectedIV` (без `ouParams` результат == базовой IV).

### C. Дубликаты формулы — мёртвый код, НЕ трогаем

Формула `1 + 0.5 * (1 - 1 / Math.sqrt(timeRatio))` встречается ещё в двух местах,
но обе копии недостижимы из приложения:

| Файл | Строки | Почему мёртв |
|---|---|---|
| `frontend/src/utils/volatilitySurface/projection.js` | 59–75 | Каталог-версия модуля. Все 17 импортов в проекте написаны как `from './volatilitySurface'` (без подпути), и сборщик разрешает это в файл `volatilitySurface.js`, а не в каталог. Импортов вида `volatilitySurface/projection` или `volatilitySurface/index` в коде нет. |
| `frontend/src/utils/volatilitySurface-old.js` | 189–203 | Архивная копия, не импортируется нигде. |

Родственные (но другие) эвристики роста `IV × sqrt(T_old / T_new)` в
`frontend/src/utils/volatilitySurface.js` строки **111–119** (`interpolateIV`) и
**280–285** (`getTermStructureRatio`) — тоже **не влияют на живое поведение**:
`interpolateIV` не импортируется ни одним модулем, `getTermStructureRatio` не вызывается.
В рамках этой задачи их не трогаем (принцип минимального изменения).
