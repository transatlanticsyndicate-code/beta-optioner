# Fix: автообновление сделок по тикерам вне встроенного списка (SAP → 404)

Дата: 2026-07-14
Тип: /fix (расширение OptionsCPbuttons)

## Симптом
Всплывающее окно «Да, обновить» для сохранённой сделки по SAP: данные не подтягивались,
на вкладке TradingView — страница 404 «Page not found». «Либо со второго раза, либо никак».
Код не менялся ~2 недели — сбой появился со стороны TradingView.

## Диагностика (подтверждено на живой сессии заказчика)
- Расширение при автообновлении строит URL доски по жёстко зашитому списку из ~19 тикеров
  (`DB_TICKER_EXCHANGE_MAP` + фьючерсные паттерны). SAP в списке нет → в адрес уходил
  «голый» символ `?symbol=SAP` без биржи.
- Заказчик работает из Панамы, только с биржами США. TradingView в этом регионе резолвит
  голый `SAP` на немецкий листинг `XETR:SAP`, где опционов нет → пустая доска / 404.
- Явный `NYSE:SAP` открывает доску корректно: сентябрьская экспирация, страйки 135/140/210,
  живые котировки. Параметры `series`/`strikes` в залогиненной сессии работают.

## Правка
`background/dbConfigRefresh.js`:
- `SAP: 'NYSE'` добавлен во встроенный список (быстрый путь).
- Новая `resolveTickerExchange(ticker)` (async): встроенный список → фьючерсные паттерны →
  кэш → поиск `symbol-search.tradingview.com` (берётся американский листинг, типы
  stock/dr/fund; код биржи из поля `prefix`, напр. «AMEX», а не отображаемого «NYSE Arca»).
- `buildTvOptionsUrl` стала async и использует резолвер; оба вызова (`dbConfigRefresh.js`,
  `pendingRefresh.js`) переведены на `await`.
- Версия расширения 1.6.25 → 1.6.26.

## Проверка
- Резолвер прогнан на 15+ тикерах: SAP→NYSE, COIN/QQQ/TLT/ASML→NASDAQ, F/XOM/GME/UBER/TSM→NYSE,
  GLD/SLV→AMEX, ARKK→CBOE. Индексные/CFD-фиды (SPCFD для SPX) отсекаются.
- Открыты доски end-to-end: `NYSE:SAP` (сент. 135/140/210, котировки есть), `AMEX:GLD` (полная доска).
- `node --check` по обоим файлам — OK.

## Осталось
Заказчику перезагрузить расширение в Chrome (v1.6.26) и проверить обновление сделки SAP.
После подтверждения — коммит.
