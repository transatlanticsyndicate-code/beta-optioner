# 🔧 Показатель «Использовано %» превышает 100% на странице Crypto

**Статус:** 🟢 Исправлено (2026-07-25)
**commit_start:** 41a6fe9 (fix/sever-gpt-double-exp-diag)

---

## 📋 Описание проблемы

**Где:** Страница Crypto
**URL:** https://crypto.optioner.online/#crypto

**Проблема:**
Показатель «Использовано %» показывает значение больше 100% (пример: 101.61%),
хотя по смыслу метрики использованная доля не должна превышать 100%.

**Причина:**
Не установлена — быстрый grep по frontend/src на "Использовано"/"used"/"usage"
ничего не нашёл (возможно, текст собирается динамически или лежит в другом
модуле). Нужно искать вручную.

---

**Где искать:**

- Если в коде фронтенда не находится — искать в бэкенде (агрегация/расчёт
  может идти там, а фронт просто отображает готовое число).

**Что проверить:**
- Как считается «Использовано %»: числитель/знаменатель, откуда данные
- Есть ли ограничение сверху (`Math.min(value, 100)`) или его нет вообще
- Не суммируются ли несколько источников с двойным учётом (отсюда >100%)
- Округление — не превращает ли округление корректное значение в 101.x%
  из-за ошибки в другом месте цепочки расчёта

«Использовано %» не должно превышать 100%. Если по бизнес-логике

уточнить у Андреса, а не считать багом по умолчанию.

## 🔎 DIAGNOSE (2026-07-25)

**Локализация:** приложение `crypto/` (Vite+TS SPA, отдельное от React
`frontend/`, см. память `reference_crypto_deploy.md`). Метрика считается в
`PositionService.calculateGlobalStats()` (`crypto/src/PositionService.ts`)
и рендерится в `crypto/src/StatsRenderer.ts`.

**Корневая причина:** в состоянии приложения существует два независимых
значения депозита:
1. `state.deposit` — статичное число, хранится в БД, обновляется только
   через экшен `UPDATE_DEPOSIT`, который нигде в текущем коде не
   диспатчится (мёртвая ветка) — то есть поле фактически заморожено.
2. Динамический депозит — сумма всех операций «Ввод» минус «Вывод
   средств» из журнала (`FinancialService.calculateDeposit`). Именно это
   число показывает карточка «Депозит» и именно так его понимает
   пользователь.

`percentUsed` в `calculateGlobalStats()` делится на (1), а не на (2).
Аналогичная метрика в `WeeklyStatsRenderer.ts` считается правильно — от
динамического депозита. Расхождение — только в глобальной карточке.

**Подтверждено на проде (read-only проверка в БД `crypto_app_state`,
2026-07-25):**
- статичный `deposit`: 1 620 436
- динамический депозит (ввод − вывод): 1 773 995
- сумма по активным позициям: 1 646 475
- 1 646 475 / 1 620 436 = **101.61%** ← ровно то значение, что видел
  пользователь
- 1 646 475 / 1 773 995 = **92.81%** ← корректное значение

Аномалии во введённых данных нет — расхождение накапливалось постепенно
(статичное поле не растёт вместе с реальными вводами), пока сумма по
позициям не превысила устаревшее число.

**Fix:** `calculateGlobalStats()` считает депозит через
`FinancialService.calculateDeposit(state.financial)` вместо
`state.deposit`. Поле `state.deposit` в типах/сторе не тронуто (используется
для валидации схемы состояния при загрузке/сохранении).
