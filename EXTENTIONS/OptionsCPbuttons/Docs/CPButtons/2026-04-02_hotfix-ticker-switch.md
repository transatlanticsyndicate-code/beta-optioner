# Hotfix: переключение тикера в калькуляторе

**Дата:** 2026-04-02
**Версия:** ext2 v1.4.4 → v1.4.5
**Pipeline:** /hotfix

---

## Что было сломано в проде

При добавлении опциона от нового тикера (например, переход ESM2026 → TSLA → AAPL):
1. Калькулятор не переключал URL — оставался на старом `?contract=ESM26`
2. React читал тикер из URL, поэтому VOL и IV подтягивались для неправильного контракта
3. При следующем добавлении позиции других тикеров накапливались в калькуляторе

## Что исправлено в ext2

**Файл:** `background/calculator.js`

**Патч 1 — смена URL при новом тикере:**
В `handleOpenOptionerTab()` при уже открытой вкладке калькулятора — сравниваем `contract=` параметр текущего URL с новым тикером. Если отличаются — обновляем URL и ждём полной загрузки перед инжектом.

**Патч 2 — фильтрация чужих тикеров при мерже:**
В `injectDataIntoCalculator()` фильтруем `knownOptions` только по текущему тикеру. Позиции TSLA/NVDA не попадают в мерж при инжекте AAPL.

## Как верифицировано

Через DevTools MCP (CDP):
- Добавлен опцион AAPL → URL калькулятора сменился на `?contract=AAPL` ✅
- `calculatorState.selectedTicker = "AAPL"` ✅
- BID/ASK/VOL/IV для всех 8 позиций AAPL совпадают между панелью расширения и калькулятором ✅
- Имитация инжекта: после записи только NVDA — через 1.5 сек TSLA не вернулись ✅

## Остаточный баг (фронтенд калькулятора)

`useExtensionData.js` при получении данных от расширения мержит их с "manual" позициями из предыдущих сессий, не очищая их при смене тикера. Лог: `{fromExtension:1, manual:3, total:4}`. Требует фикса в `UniversalOptionsCalculator.jsx` — при смене `selectedTicker` сбрасывать manual-позиции других тикеров. Передано Андрею.
